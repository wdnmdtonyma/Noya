# 写作任务新建与切换

Status: ready-for-human

日期：2026-10-04。独立增量规格；基于已实现的本地 Agent 任务界面，保留原规格与已交付实现基线。用户已确认同作品新建任务、返回旧任务继续的范围，本轮先交付文档。

## Problem Statement

作者只能进入每部作品最近的任务，无法为新的写作目标开启独立任务并回来继续旧稿。仅添加新建按钮还会使旧任务的命令、输入、稿件引用及中断同步被“最新任务”替代。

## Solution

在现有任务页面增加当前作品的轻量任务入口，支持新建、选择与继续明确的写作任务。新任务使用作品当前正式资料，拥有独立 Context 对话与产物。查看任务和运行任务分别管理，保持同一服务仅一个活动作者任务，并精确恢复所选任务及真正未完成的同步。

## User Stories

1. 作为作者，我想在当前作品中新建任务，以便开始另一个明确的写作目标。
2. 作为作者，我想直接进入空白任务，以便不必先填名称或章节。
3. 作为作者，我想创建成功后再切换，以便失败不会清空旧输入。
4. 作为作者，我想创建重试不会产生重复任务，以便不会误留多个空白起点。
5. 作为作者，我想每条任务都有可区分的名称与时间，以便找到自己的工作。
6. 作为作者，我想新任务使用现有正式资料，以便保持同一部作品的连续性。
7. 作为作者，我想旧任务的讨论、废案与未定稿内容不会自动进入新任务，以便独立探索新的方向。
8. 作为作者，我想新任务可以先讨论和查询，以便不被自动推进到写稿。
9. 作为作者，我想看到当前作品的所有已有任务，以便找回较早的工作。
10. 作为作者，我想切回非最新任务继续对话，以便不必复制历史记录。
11. 作为作者，我想在旧任务阅读和修改原稿，以便修改始终针对正确版本。
12. 作为作者，我想各任务的输入、引用和阅读位置分别保存，以便切换时不串用内容。
13. 作为作者，我想待回答的问题留在原任务，以便确认具有明确对象。
14. 作为作者，我想其他任务更新资料后旧确认被重新校验，以便不会用过期内容覆盖作品。
15. 作为作者，我想旧写手无法恢复时得到说明和重新安排，以便仍可继续工作。
16. 作为作者，我想运行中可以新建和查看别的任务，以便利用等待时间。
17. 作为作者，我想看见实际执行的作品与任务，以便可以准确返回。
18. 作为作者，我想明确停止指定任务并等它停稳，以便再开始另一任务。
19. 作为作者，我想晚到消息保留在原任务，以便当前页面不会出现错位结果。
20. 作为作者，我想多个页面遵守同一个执行限制，以便不会意外并行写作。
21. 作为作者，我想新建任务时仍知道作品有待同步章节，以便不会用旧资料继续写作。
22. 作为作者，我想返回负责同步的任务处理冲突或继续，以便不丢已有决定。
23. 作为作者，我想旧数据没有同步任务时可以明确承接，以便完成同步后继续写作。
24. 作为作者，我想承接同步后始终能找回该任务，以便切换或重启不会重置停止状态。
25. 作为作者，我想再次定稿时清楚知道同步对象变了，以便旧清单不污染新正文。
26. 作为作者，我想重开页面恢复上次查看的具体任务，以便不总被带到最新任务。
27. 作为作者，我想进程退出后看见真实中断状态，以便决定如何继续。
28. 作为作者，我想旧任务的中断同步不被新空白任务遮住，以便能完成已接受章节的后续工作。
29. 作为作者，我想升级后保留现有任务和输入，以便无需手动搬迁。
30. 作为作者，我想某条任务损坏时仍能使用其他正常任务，以便一个记录问题不会阻断整部作品。

## Implementation Decisions

### 1. 扩展现有任务入口

- 继续复用 LocalApp、共享 ModelRuntime、openWritingSession、TaskHub、现有角色工具和单任务占用。任务新建、枚举、明确选择均进入同一本机应用边界，不增加另一套编排。
- 保留作品身份，任务身份始终与作品一起校验。页面选择、读取正文和执行命令指向明确 TaskRef，不再先解析最新任务后比较是否一致。
- openWritingSession 增加恢复指定已保存任务的能力；页面提交已选任务时不得再次隐式选择最新任务。CLI 原有新建和继续最近任务的语义保持兼容。
- 区分读取记录、首次打开指定运行时和重连已有运行时。查看及刷新不触发模型，不调用会把活跃子 Agent 标为中断的恢复操作；活跃运行时继续复用。

### 2. 任务创建与发现

- 创建任务只持久化独立任务登记和空白页面状态，不创建新作品，不启动 Context 或子 Agent。已有作品没有任务时沿用首个任务的创建行为；并发首次进入不得重复创建首个任务。
- 创建请求具有稳定请求身份，返回明确作品及任务身份。以持久化的创建请求与任务关联处理重复点击、响应丢失和重启后重试；同一请求只返回原任务，不能仅用内存去重。
- 可以为任务登记增加兼容旧记录的可选创建请求元数据；不改作品正式内容 schema，不搬动会话及产物。写入未确认成功时不把未登记的目录当作健康任务。
- 任务摘要包含身份、创建时间、可区分显示名称、执行状态、待作者决定情况和单条读取错误。名称由首条作者消息开头确定性生成；未发言使用创建时间与短标识，不额外调用模型命名。
- 列表按创建时间倒序，同时间用稳定身份定序。损坏项单独标识，不使整份列表失败。已选任务无效时显示错误并允许重新选择，不能把正在提交的操作改投另一任务。

### 3. 确切的任务内容与读取隔离

- 每条任务保留自己的 Context 会话、Writing Package、初稿、检查、同步提案、决定和请求记录。产物局部身份可重复，完整引用必须包含作品、任务和产物身份。
- 新任务不复制旧消息、不接收旧任务通知，也不自动加载其他任务临时材料；正式资料及定稿正文由当前作品共享。
- 页面任务的通用读取、列举和搜索须限制在当前任务工作材料、作品正式资料与现有流程说明中。仅新建会话或提示模型不要读旧稿不算隔离；显式读取其他任务、从作品根递归搜索都不能返回其他任务临时内容。
- 保持现有正式资料查询、当前任务稿件读取和各角色工具可用；不新增跨任务素材导入或检索授权流程。作者想继续旧稿时回到旧任务。
- 返回旧任务恢复原作者目标和保存材料，后续资料读取以当前正式内容为准。旧 Writer 不可恢复时按现有流程说明并重新安排，不假称其仍存活。

### 4. 页面选择与本地输入

- 页面持有明确的当前作品和任务；每部作品保存上次选择的任务。没有选择偏好时回退最新创建的健康任务；保存的选择失效时显示错误并让作者重选。无健康任务时说明情况，不能自动覆盖损坏记录。
- 输入、稿件引用、阅读对象及滚动位置以作品与任务为边界保存。切换前保存原任务输入；异步发送完成后只清理提交时对应任务的已发送内容。
- 晚到快照、创建响应、正文读取和发送结果需核对请求发出时的目标与当前选择。作者已经切换时，结果仍保存到原对象，不强制跳回或清空当前任务。
- 同服务不同标签页独立保持正在查看的任务；另一页面创建任务不改变本页选择。旧请求中的任务身份仍有效，不因同作品有新任务而被判定为“只能操作最新任务”。
- 初次升级将旧版按作品保存的输入、引用和阅读偏好一次性绑定到原本对应的最近任务；先验证归属再迁移，读取失败时保留原偏好，不能在每次新建时再次复制。旧偏好没有任务身份，若存在多个可能的任务或相同稿件编号而无法确认，保留旧内容并让作者确认所属任务，不自行按最新任务猜测。

### 5. 应用行为契约

| 行为 | 必须提供或确定的对象 | 结果与约束 |
| --- | --- | --- |
| 列出任务 | 明确作品 | 返回任务摘要及单项错误，不启动模型 |
| 新建任务 | 作品与稳定创建请求身份 | 保存后返回明确任务；允许其他任务运行中创建；重试返回同一结果 |
| 读取任务 | 明确作品及任务 | 返回该任务快照、作品待同步信息与服务活动任务，不重新选择最新任务 |
| 发送、回答、修改、定稿、继续 | 明确任务及必要的产物或决定引用 | 校验归属、最新领域状态与全局占用；复用现有命令去重 |
| 返回执行任务或停止 | 服务实际活动任务 | 精确到任务；同作品另一任务也属于“其他任务” |
| 返回同步任务 | 章节当前正式版本及其同步任务 | 定位原任务；仅改变查看对象，不自动回答、继续或停止 |
| 承接旧数据同步 | 章节当前正式版本、目标任务、明确作者动作 | 原子校验无有效承接者后保存归属；之后所有入口均指向该任务 |

传输方式沿用当前服务，无需为了新增任务引入事件总线。新建、只读选择和模型执行分别处理；服务端业务校验不能依赖前端禁用按钮。

### 6. 同作品多任务执行

- 保持一个活动作者任务，身份比较使用作品与任务整体，不能继续仅判断是否另一个作品。占用覆盖 Context、子 Agent 及未处理完的自动通知。
- A 执行时允许创建或查看 B，并保存 B 输入；B 的消息、决定、定稿和继续执行受阻。停止 A 显示停止中，真正停稳后再释放占用，保留成果。
- A 等待作者决定且实际没有执行时，可执行 B。A 的决定保留；B 运行时不能通过回答 A 的决定绕过占用。决定内容及正式资料发生变化时沿用过期确认校验。
- 所有消息、流式内容、正文版本和运行通知按任务归属分发，单任务仍按既有方式使用多个角色。

### 7. 待同步章节与承接任务

- 待同步事实仍来自作品正式资料。新建或选择任务不修改该事实；需要保存 Writing Package 或安排 Writer 生成、重写时，沿用现有待同步门禁。纯措辞修订仍保存为任务初稿。
- 在最小作品运行元数据中关联“章节当前正式版本、负责同步的 TaskRef”。正常定稿建立或更新该关联；它用于定位任务，不能替代正式正文与待同步状态作为业务真源。
- 同步归属同时是工具执行的约束。TaskHub 保存同步清单和应用同步时，必须校验当前任务负责该章节的当前正式版本；应用时在既有写入锁内再次校验。非负责任务返回应处理的任务信息，不能另建清单或写入，更不能通过“继续”提示越过原任务的作者停止或待决定状态。
- 当前正式版本还需识别定稿动作的任务、稿件及事件，不能仅以正文内容相同来认定是同一次定稿。相同正文在另一任务重新定稿时，仍按新定稿更新归属与旧决定有效性；页面的“当前正式版本”须与此一致。
- 建立新关联或重新定稿时，与当前正式版本校验和现有写入串行化保持一致。失败或崩溃后若正式正文已保存而关联未完成，需能根据定稿登记和当前正文恢复；不能错误地回退正文或随机选择最新任务。
- 旧数据没有关联时先依据同作品定稿登记和当前正式正文寻找可验证的归属；无法可靠确定且记录健康时，才提供作者明确承接。记录损坏或存在尚待决定、明确停止的既有承接任务，不算“无人承接”。
- 明确承接必须先检查全局执行占用和章节版本，再持久化唯一归属；冲突、失败、作者停止和重启都保留此归属。两个标签页并发承接只能有一个成功，其他入口返回已选任务。
- 新任务需要写作时显示待同步章节及对应任务，作者回到原任务完成后，再回新任务明确继续；不自动串起另一个作者任务。
- 重新定稿同一章是明确的版本变更：新定稿任务负责同步，旧提案、旧决定和旧自动恢复候选失效。旧任务保留历史，只展示当前同步已转移，不能用旧清单写入新版本。
- 有多章待同步时逐章显示当前承接任务；不为每章启动并行执行。正常新建与查看不允许接管其他任务的决定。

### 8. 重连与恢复

- 浏览器重开恢复明确选择，独立查询实际活动任务。不能因浏览器选择 B 而重开、终止或自动继续 A，也不能因为创建了 B 而忘记 A 的活动占用。
- 进程启动时按真实任务记录恢复中断状态，扫描已有任务与有效同步归属，不再只检查各作品最新任务。允许恢复的同步候选必须对应当前正式版本，且没有作者停止或待决定标记。
- 保持全局单任务限制，一次只恢复一个符合条件的同步任务，其余仍有明确入口；不新增后台队列，也不伪造作者输入或重新定稿。记录缺失、归属不确定时要求明确处理，不能自动猜测承接者。
- 恢复指定旧任务沿用已有会话、任务登记和产物。查看不会创建新 Context；继续时才按需打开精确任务，无法继续的记录明确报错并保留现场。

## Testing Decisions

复用作者已确认的“真实页面 → 本机应用 → openWritingSession → 真实工具和存储”边界，自动化只替换共享 ModelRuntime 的模型响应。已有会话测试验证新任务不继承旧对话；本机应用测试已有 HTTP、产物、作者确认、单任务占用与恢复先例。本轮扩展同一作品的两个任务，再加另一作品，避免只测跨作品而漏同作品。

好测试断言可观察行为、身份、实际保存内容和错误，不断言内部类拆分或复制实现。新字段与辅助函数不各自制造测试接口；竞争和故障可从同一本机应用边界注入，关键旅程在浏览器操作。

| 验收组合 | 必须证明 |
| --- | --- |
| 已有作品新建两次；同请求重复、并发、响应丢失后重试 | 两次明确创建产生不同任务；同一次请求只产生一个；原输入不丢 |
| 同一作品 A 有临时唯一标记，B 从空白开始 | B 没有 A 的消息、通知、旧稿及隐式材料；正式资料可正常查询 |
| B 尝试直接读取 A、从作品根递归搜索 | 工具边界不返回 A 的临时材料；当前任务和正式资料查询仍正常 |
| A、B 都存在相同局部稿件编号 | 阅读、修改、确认与定稿不串任务；跨作品或错配引用被拒 |
| B 已成为最新任务，再返回 A | 原 Context、消息、稿件及继续动作属于 A，不落到 B |
| A 运行期间同作品新建、查看 B | A 不被取消，B 可读但不可执行；停止与返回明确指向 A |
| 两标签页选择不同任务并竞争执行 | 只有一个活动作者任务，迟到结果和输入清理不污染另一任务 |
| A 待确认，B 修改正式资料后回 A | 旧确认被拒并重新呈现，不用旧授权覆盖新资料 |
| A 同步待决定或被停止，B 请求生成或内容重写 | 定位 A 而不接管，门禁不能通过新任务绕过 |
| A 已停止或待决定，B 的 Context 直接调用保存清单或应用同步 | 工具拒绝非负责任务，正式资料与 A 的状态不变；写入前仍核验当前版本和归属 |
| 无归属旧数据在 B 承接，再进入 C 或重启 | 唯一归属保留，C 返回 B；停止与待决定不因切换被绕过 |
| B 重新定稿 A 的同一章，包含正文完全相同的情况 | 归属随新定稿动作更新，当前正式版本显示准确；A 的提案、决定和恢复不再作用于新版本 |
| A 同步中断，B 是后来创建的空白任务 | 启动恢复选中有效的 A，不能仅按最新创建任务处理 |
| 升级已有 CLI 与页面任务 | 历史任务可选择，旧界面偏好只迁移一次，既有 CLI 语义和记录不变 |
| 损坏单个任务、失效选择及断线 | 错误明确，健康任务仍可进入，不静默改投最新任务 |

真实验收使用独立作品：在 A 讨论并留下未定稿短稿，新建 B，用正式资料开始另一段独立讨论，再切回 A 修改指定版本并定稿同步；刷新和重启后继续非最新任务，核对保存结果及隔离。独立审查和文档检查不等于这些实现测试已完成；实现阶段分别记录可控模型、浏览器和真实模型结果，不用文学质量评价替代身份与保存验收。

## Out of Scope

- 并行作者任务、跨进程协调、任务调度平台和托管服务。
- 任务删除、归档、复制、分叉、批量管理和跨任务未定稿素材带入。
- 独立任务管理页面、直接正文编辑、模型设置与新的写作角色。
- 通用操作级恢复或事件溯源框架，及对模型内部动作的精确续跑。
- 新增使用统计或数据看板，延续上一版已确认的本地自用 MVP 范围。
