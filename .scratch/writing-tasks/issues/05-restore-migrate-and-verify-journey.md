# 05 — 刷新、重启及旧数据升级后的完整恢复

**What to build:** 作者刷新页面、重启本机服务或升级已有数据后，继续上次选中的具体任务，保留输入和阅读内容，并看见真实的执行与中断状态。中断同步回到真正负责它的任务，损坏记录不会阻断其他任务；完成整段多任务旅程的浏览器和真实模型验收。

**Blocked by:** 04 — 定稿后回到正确任务完成资料同步。

**Status:** ready-for-agent

- [ ] 原型与真实页面覆盖恢复非最新任务、进程中断、已保存选择失效、旧偏好归属待确认和单条任务损坏，提示清楚且有可继续的入口。
- [ ] 刷新或重开作品时优先恢复该作品上次查看的具体任务、输入、稿件引用与阅读位置；没有选择记录才进入最新创建的健康任务。保存的选择失效时说明问题并让作者重选，无健康任务时不自动覆盖损坏记录。
- [ ] 页面重连单独查询真实活动任务，查看 B 不重开、停止或自动继续 A，不重发上一条消息；活跃运行时继续复用。明确继续旧任务时才按需打开它，恢复失败明确报错并保留记录。
- [ ] 服务退出后，原执行显示真实中断状态，已经保存的讨论、产物和定稿仍在；恢复不伪造作者输入、不重新定稿，也不承诺从模型内部某个动作精确续跑。
- [ ] 启动恢复扫描实际任务及有效同步归属，A 同步中断后即使新建了空白 B，仍定位当前正式版本对应的 A。作者明确停止、仍待决定、已被重新定稿替代或归属不确定的任务不自动恢复。
- [ ] 恢复遵守全局单任务限制，一次只恢复一个符合条件的同步任务，其余保留明确入口；不引入后台队列或通用操作恢复框架。
- [ ] 已有 CLI 与页面任务可直接选择，保留登记、会话和产物，CLI 原有行为不变。旧版按作品保存的输入、引用与阅读偏好只迁移一次，并先验证其原任务归属。
- [ ] 旧偏好存在多个可能任务、相同稿件编号或读取失败时，保留原内容并让作者确认所属任务，不猜测最新任务、不丢弃、不复制给每个新任务；作者确认后后续创建不再重复迁移。
- [ ] 损坏单条任务或遇到断线时明确报错，其他健康任务仍可访问；请求不静默改投其他任务。对记录缺失或损坏的同步归属，不冒充无主状态自动承接。
- [ ] 在真实本机服务、写作会话、工具与存储边界，仅替换模型响应，覆盖非最新任务重开、活跃任务重连、进程中断、同步恢复候选筛选、旧偏好一次迁移和归属不明、损坏隔离；核对实际保存内容。
- [ ] 用独立验收作品完成真实浏览器与真实模型旅程：在 A 留下未定稿短稿，新建 B 用正式资料独立讨论，再回 A 修改明确版本并定稿同步；刷新、重启后继续非最新任务，证明隔离、保存和恢复。浏览器验收还包含另一作品及两个标签页的执行和选择边界。
- [ ] 保存可复现的操作步骤、观察结果和验证证据，分别记录原型检查、可控模型自动化、真实浏览器及真实模型验收；逐项对照父规格的验收组合，有未完成或失败项如实记录，不用文学质量评价替代身份与保存结果。
