# 04 — 定稿后回到正确任务完成资料同步

**What to build:** 作者在明确任务中对明确版本定稿后，正文立即保存，后续资料同步始终能定位到负责该正式版本的任务。在其他任务开始写作时，页面引导作者回原任务处理同步；旧数据可明确承接，再次定稿会使旧同步决定失效。原型、页面提示和真实工具共同落实此边界。

**Blocked by:** 02 — 回到旧任务继续写作与修改；03 — 运行期间查看其他任务与停止执行。

**Status:** ready-for-agent

- [ ] 原型与真实页面覆盖待同步提示、返回同步任务、原任务已停止或待决定、旧数据明确承接，以及重新定稿后同步转移；返回只改变查看对象，不自动回答、继续或停止任务。
- [ ] 定稿始终使用作者确认的任务及稿件版本，替换已有正式正文前明确告知。正式正文立即保存并标记待同步，同步失败不回退成初稿；正常定稿建立对应当前正式版本的同步任务归属。
- [ ] 归属能识别此次定稿的任务、稿件与定稿动作。另一任务重新定稿同一章时，即使正文完全相同，也更新归属与页面“当前正式版本”，使旧提案、旧决定和旧自动恢复候选失效；旧任务保留历史并说明已被替换。
- [ ] 保存正式正文与同步归属遵守现有写入串行化；正文已保存而归属尚未完成的故障，可根据定稿登记与当前正式正文恢复确定的归属，不回退已接受正文、不猜测最新任务。
- [ ] 作品有待同步章节时，其他任务仍可创建、查看、讨论和查询；保存 Writing Package 或安排 Writing Agent 生成、内容重写前受现有门禁约束。纯措辞修订仍可沿原流程保存为未定稿版本。
- [ ] 页面列出待同步章节及各自的负责任务。作者在原任务处理停止或冲突决定，完成同步后回此前任务明确继续写作，不自动执行另一任务，也不为多章启动并行同步。
- [ ] 保存同步清单与应用同步的工具均校验当前任务是否负责当前正式版本，应用时在既有写入锁内复核；非负责任务只得到正确任务的定位信息，不能另建清单或应用变更，不能通过“继续”绕过原任务的停止或待决定状态。
- [ ] 无归属的旧数据先用同作品定稿登记和当前正式正文寻找可验证的任务；确实无法可靠定位且记录健康时，才提供作者明确在当前任务承接的操作。损坏记录、不确定的原归属或既有停止与待决定任务不能当作无人承接。
- [ ] 明确承接校验全局执行占用与当前章节版本，原子保存唯一归属；两个标签页并发承接只能一个成功。切换、冲突、失败、停止与重启后均保留归属，其他入口返回既有承接任务。
- [ ] 在真实本机应用与工具、存储边界，仅替换模型响应，验证非负责任务直接保存或应用同步被拒、等待决定或停止不能被绕过、并发承接、定稿中断后的归属重建，以及正文相同和不同两种重新定稿后旧决定失效。
- [ ] 在浏览器完成“在 A 定稿待同步 → 去 B 请求生成或内容重写 → 返回 A 处理 → 回 B 明确继续”，核对正式资料和原决定保留；另演示旧数据承接后停止，再从第三个任务返回该承接任务。服务启动后的候选扫描与自动恢复由 05 完成。
