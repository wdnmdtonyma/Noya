# 03 — 运行期间查看其他任务与停止执行

**What to build:** 任务 A 执行时，作者能新建或查看任务 B、阅读已有内容并保留输入，同时清楚看见实际执行的任务，准确返回或停止 A。原型和真实应用都区分“当前查看”与“正在执行”，同作品、跨作品和多个标签页遵守同一个执行限制。

**Blocked by:** 01 — 新建并切换独立写作任务。

**Status:** ready-for-agent

- [ ] 原型与真实页面覆盖 A 执行时查看 B、返回 A、停止中和停止完成。运行提示包含实际作品与可区分的任务信息；同一作品的另一个任务同样显示为其他执行任务。
- [ ] A 讨论、写稿、检查或同步时，B 可以创建、查看和输入，A 不被取消；B 的发送、回答决定、定稿与继续执行由服务端拒绝，并提供返回或停止 A 的入口，不能只依赖按钮禁用。
- [ ] 返回执行任务精确选中 A，不启动或重启它；停止明确针对 A，覆盖 Context、子 Agent 及尚未处理完的自动通知。真正停稳后才释放执行占用，已有消息和成果保留。
- [ ] A 等待作者决定且没有后台执行时释放占用，B 可开始执行；A 的决定仍保留，B 执行时不能通过回答 A 的决定绕过占用。运行、停止中和待决定状态不混为一谈。
- [ ] A 的晚到消息、流式输出、稿件和状态更新只进入 A，不覆盖 B 的内容、不清理 B 的输入，也不改变作者当前选择。
- [ ] 同一服务的两个标签页可独立查看不同任务，竞争执行时最多一个作者任务成功占用；同作品与跨作品均遵守该规则。不新增并行任务、跨进程协调或调度框架。
- [ ] 在真实本机应用与写作流程中，仅替换模型响应，控制任务完成、通知和停止时机，验证单任务占用、停止后才释放、待决定释放和晚到结果归属；从服务入口直接发起竞争操作，证明前端之外也受约束。
- [ ] 在浏览器用同作品两个任务和另一作品演示新建、查看、返回与停止，并用两个标签页验证选择互不跳转、输入保留和执行竞争，记录观察结果。
