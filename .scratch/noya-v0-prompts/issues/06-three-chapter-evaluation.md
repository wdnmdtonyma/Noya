# P6 — 连续三章评估与汇总

**What to build:** 在一本从零开始的书上，用定稿的 SP 与 Skills 连续写三章（S3–S6 循环），每章做对照比较，并汇总回答 v0 的两个问题：A（检查返修是否让文章更好、代价多大）与 B（软流程是否可靠、门禁拦住了什么）。汇总给出下一步建议：哪些环节保留、改进或砍掉，哪些软规则应移入代码。

契约详见 `.scratch/noya-v0-prompts/spec.md`："评估场景"、"指标与迭代"。

执行者：架构负责人；对照比较的阅读与选择由作者完成。

**Blocked by:** P4、P5、实现 10、实现 11

**Status:** ready-for-agent

- [ ] 同一本书连续三章完成：每章都有 Package、检查、定稿、同步
- [ ] 每章完成 `/compare` 与 `/compare-pick`（作者盲读选择并写理由）
- [ ] 每个任务运行 `noya audit`，报告归档
- [ ] 汇总文档含：场景通过率；跳过方案检查或正文检查的次数；门禁拒绝按原因分类及处理是否正确；对照比较结果与理由摘要；检查员 violation 抽查属实率；每章返修轮数；每章各角色 token 与耗时
- [ ] 汇总给出对 A、B 的结论（样本量有限时如实说明），以及保留 / 改进 / 砍掉 / 移入代码的具体建议
- [ ] 汇总保存在仓库文档中，作为 v0 之后工作的输入
