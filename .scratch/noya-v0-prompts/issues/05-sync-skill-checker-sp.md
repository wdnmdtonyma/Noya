# P5 — 同步核对员 SP + Context 同步 Skill

**What to build:** 作者 `/finalize` 后，Context Agent 按 Skill 自动开始同步：列出正文实际带来的资料变化（必含本章摘要与重要登场角色），每条附原文摘录；派同步核对员逐条核对；有依据的写入，无依据的删除或修正，冲突的交作者决定；最终清除待同步标记。定稿后、同步前作者要求写下一章时，Context Agent 在被拒后先完成同步。同步核对员只判定、不补充，不把"资料没记录"当冲突。

契约详见 `.scratch/noya-v0-prompts/spec.md`："Skill：Context 同步"、"同步核对员 SP"、评估场景 S6、S7。

执行者：架构负责人。

**Blocked by:** P1、实现 09（仅限真实运行验证）

**Status:** ready-for-agent

- [ ] 同步 Skill 与核对员 SP 各不超过约 1500 汉字
- [ ] S6（定稿后同步，含一处需要作者决定的变化）连续两次通过：自动开始同步；清单含 `chapter_meta`；有争议项询问作者；同步后待同步清除
- [ ] S7（同步前要求写下一章）连续两次通过：被拒后转入同步，不反复重试
- [ ] 抽查同步清单：仅被提及的人物、正文未确认的推测没有进入清单（人工核对并记录）
- [ ] 审计中每份清单的核对次数不超过 2（反复派核对员"挑到满意为止"视为失败）
- [ ] 迭代日志记录修改与结果
