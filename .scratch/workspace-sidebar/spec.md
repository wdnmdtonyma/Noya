# 作品与写作任务侧边栏

Status: ready-for-human

日期：2026-10-06。设计依据是 `docs/prd/subagent-progress/prototype.html` 中的左侧栏（固定样例，只验证交互，不作为实现证据）。《查看 Agent 执行过程》规格（`.scratch/subagent-progress/spec.md`）只覆盖信息流、子任务卡片、右侧详情和输入区，写明"顶栏的作品切换和任务列表保持原样"，原型里的侧边栏因此没有实现。本规格把这块单独补上。PRD 中"作品侧栏的任务列表仍显示任务状态"一句也以本规格为准。

## Problem Statement

作者在任务页里写作时，作品和写作任务的切换藏在两个弹窗后面：

- 顶栏的作品名要点开一个模态弹窗才能换作品；
- 任务标题旁的"写作任务"要再点开另一个模态弹窗，才看得到本作品有哪些任务、哪个在执行、哪个在等自己决定。

结果是：

- 作者看不到其他任务的状态。另一条任务执行完、失败或等待决定时，作者不打开弹窗就不知道。
- 换任务要"打开弹窗 → 选择 → 弹窗关闭"三步，来回比较两个任务很费劲。
- 顶栏占了一整行高度，却只放品牌、作品名和连接状态。
- 原型已经确定用一条可收起的左侧栏承载这些内容，现在的页面和原型不一致。

## Solution

把顶栏和两个选择弹窗换成一条左侧栏，常驻在任务页左边：

- 侧栏从上到下依次是：品牌与收起按钮；当前作品（点开切换作品）；新建任务；本作品的写作任务列表，每行带状态；底部是本机连接状态。
- 当前任务在列表里高亮。点任意一行直接切到该任务，不再经过弹窗。
- 桌面上侧栏可以收成一条只留图标的窄栏，把宽度让给信息流：
  - 窄栏里每个图标都在原来的位置，收起只是裁掉宽度，不重排；
  - 悬停或键盘聚焦时，旁边浮出提示；
  - 任务图标上的小圆点提示有任务在执行或失败；
  - 点任务图标会在侧面弹出任务列表。
- 可以用 ⌘\（Windows/Linux 上是 Ctrl+\）展开或收起。收起状态在刷新后保留。
- 窄屏上侧栏变成从左侧滑出的抽屉，由任务标题旁的按钮打开。选择任务、点遮罩或按 Escape 都会关上抽屉。
- 任务标题上方显示"作品名 / 写作任务"，作者收起侧栏后仍知道自己在哪部作品里。

## User Stories

### 侧栏的基本结构

1. 作为作者，我想在任务页左侧一直看到当前作品和它的写作任务，以便不打开弹窗就知道自己在哪、还有哪些任务。
2. 作为作者，我想侧栏顶部显示 Noya 品牌和"让故事继续"，以便页面去掉顶栏后仍有清楚的身份。
3. 作为作者，我想当前作品显示为一张带首字封面、作品名和"N 个写作任务"的卡片，以便一眼确认当前作品。
4. 作为作者，我想点当前作品卡片，就在它下方弹出作品列表，以便不离开任务页就能换作品。
5. 作为作者，我想作品列表标出当前作品、正在执行的作品和读取失败的作品，以便不会误进出错的作品。
6. 作为作者，我想作品列表里仍能新建作品，以便新建入口不随弹窗一起消失。
7. 作为作者，我想作品列表可以用 Escape、点外部或再点一次卡片关闭，关闭后焦点回到卡片，以便键盘操作连贯。
8. 作为作者，我想侧栏里有一个"新建任务"按钮，以便随时开始一条独立讨论。
9. 作为作者，我想新建任务时按钮显示"正在保存新任务…"，上次结果未确认时显示"确认上次创建结果"，以便沿用现有的创建去重行为。
10. 作为作者，我想断线时"新建任务"不可点，并提示"连接恢复后可用"，以便知道为什么点不动。
11. 作为作者，我想新建任务列表上方有"写作任务"和总数，以便知道本作品有几条任务。
12. 作为作者，我想任务列表只列当前作品的任务，按创建时间倒序，以便与现有任务列表顺序一致。
13. 作为作者，我想每行显示任务名和一行状态，以便不切过去也知道它的进展。
14. 作为作者，我想状态行按"记录损坏 → 执行中 → 正在停止 → 待决定 → 执行失败／已中断／已停止 → 创建时间"的优先级显示一种，以便最需要关注的状态不被掩盖。
15. 作为作者，我想执行中的任务前面是跳动的小圆点，失败为红点，停止、中断为黄点，其余为灰点，以便扫一眼就分辨状态。
16. 作为作者，我想只有真正在执行、且本机连接正常的那条任务显示跳动圆点，以便断线时不会误以为它还在跑。
17. 作为作者，我想断线时所有任务的圆点改成黄色，以便知道这些状态是最后已知的。
18. 作为作者，我想当前任务这一行高亮并在左边有一条竖线，以便在长列表里找到自己。
19. 作为作者，我想点任意一行直接切到该任务，以便不用经过弹窗。
20. 作为作者，我想记录损坏的任务行不能点，并显示"记录损坏"，以便不进入一个打不开的任务。
21. 作为作者，我想任务很多时列表在侧栏内滚动，品牌、作品、新建任务和连接状态保持不动，以便常用按钮总在原处。
22. 作为作者，我想任务名太长被截断时，悬停可看到完整名称，以便区分开头相同的任务。
23. 作为作者，我想侧栏底部显示"本机已连接"或"连接中断"，以便连接状态有固定位置。
24. 作为作者，我想任务标题上方显示"作品名 / 写作任务"，以便收起侧栏后仍知道当前作品。
25. 作为作者，我想原来的顶栏和两个选择弹窗不再出现，以便同一件事只有一个入口。
26. 作为作者，我想断线提示和"另一条任务正在执行"的提示仍在主区域顶部显示，以便这些提示不因顶栏移除而消失。

### 桌面收起为窄栏

27. 作为作者，我想点侧栏右上角的按钮把侧栏收成窄栏，以便信息流和右侧详情有更多宽度。
28. 作为作者，我想收起后品牌标记的位置变成展开按钮，悬停时标记换成展开图标，以便知道从哪里展开。
29. 作为作者，我想按 ⌘\（Windows/Linux 上 Ctrl+\）随时展开或收起，以便不用找按钮。
30. 作为作者，我想收起按钮的提示里显示这个快捷键，以便学会它。
31. 作为作者，我想收起和展开时每个图标都留在原来的位置，只有宽度变化，以便动画过程中不跳动。
32. 作为作者，我想收起后作品卡片只留首字封面，点它在侧面弹出作品列表，列表标题写"作品名 · 切换作品"，以便窄栏里也能换作品。
33. 作为作者，我想收起后"新建任务"只留加号图标，功能不变，以便窄栏里也能新建。
34. 作为作者，我想收起后任务列表隐藏，换成一个任务图标，以便窄栏保持简洁。
35. 作为作者，我想本作品有任务在执行时任务图标上有跳动的小圆点，有失败时是红点，以便收起后也不错过状态变化。
36. 作为作者，我想点任务图标在侧面弹出任务列表，每行带状态圆点和状态文字，底部有"新建任务"，以便窄栏里也能切换和新建任务。
37. 作为作者，我想弹出的任务列表打开时焦点落在当前任务上，可以用 Escape 或点外部关闭，以便键盘操作连贯。
38. 作为作者，我想收起后悬停或用键盘聚焦任一图标，旁边浮出名称和补充信息（如当前作品名、"N 个 · 当前「任务名」"），以便不展开也知道图标是什么。
39. 作为作者，我想提示悬停一小会儿才出现，连续扫过多个图标时则立即切换，以便提示不闪烁也不迟钝。
40. 作为作者，我想展开状态下只有收起按钮和被截断的任务名有提示，以便展开时不被多余提示打扰。
41. 作为作者，我想键盘焦点在侧栏里时切换收起状态，焦点落到对应的展开或收起按钮上，以便不丢失焦点。
42. 作为作者，我想收起状态在刷新、切换任务和切换作品后都保留，以便不用每次重新收起。
43. 作为作者，我想浏览器不允许本地保存时侧栏默认展开且照常可用，以便保存失败不影响使用。
44. 作为作者，我想打开右侧子任务详情或成果阅读时侧栏状态不变，以便布局不被自动改动。
45. 作为作者，我想页面首次加载时侧栏直接显示在保存的状态，不播放收起动画，以便刷新时不晃动。

### 窄屏抽屉

46. 作为窄屏作者，我想侧栏默认隐藏，信息流占满屏幕宽度，以便手机上有足够阅读空间。
47. 作为窄屏作者，我想任务标题左边有一个打开侧栏的按钮，以便找到作品和任务。
48. 作为窄屏作者，我想侧栏从左侧滑出，宽度不超过屏幕的 86%，背后有半透明遮罩，以便知道它是临时打开的。
49. 作为窄屏作者，我想点遮罩、按 Escape、点关闭按钮或选中一个任务都会关闭抽屉，以便切换后直接回到信息流。
50. 作为窄屏作者，我想抽屉打开时焦点进入抽屉，关闭后回到打开按钮，以便键盘和读屏操作连贯。
51. 作为窄屏作者，我想抽屉关闭时侧栏里的按钮不可聚焦，以便 Tab 不会跳进看不见的内容。
52. 作为窄屏作者，我想全屏打开成果阅读时侧栏也不可操作，以便焦点限制在阅读器里。
53. 作为窄屏作者，我想抽屉里的内容与桌面展开状态一致，以便不需要学两套界面。
54. 作为窄屏作者，我想窄屏不出现窄栏和悬停提示，以便触屏上没有无法关闭的提示。
55. 作为作者，我想把窗口在宽窄之间拖动时侧栏随之切换形态，且不留下打开的遮罩或弹出列表，以便调整窗口不出错。

### 与现有行为的衔接

56. 作为作者，我想从侧栏切换任务时，原任务的未发送输入、阅读位置和展开状态照常保存，新任务恢复自己的记录，以便沿用现有的按任务保存。
57. 作为作者，我想切换任务时子任务详情、子任务列表和侧栏的弹出列表都自动关闭，以便不把旧任务的内容带到新任务。
58. 作为作者，我想另一条任务在执行时，侧栏里那一行持续显示执行中，以便我在别的任务里也知道它还在跑。
59. 作为作者，我想任务状态变化随现有轮询更新到侧栏，且侧栏刷新不打断我的滚动、焦点和打开的弹出列表，以便侧栏不抖动。
60. 作为作者，我想侧栏读取失败的任务和作品与原来弹窗一样单独标识，健康的照常可进，以便一处损坏不拖垮整个列表。
61. 作为作者，我想首次没有作品时仍看到"开始第一部作品"的空态，侧栏里作品卡片提示"选择作品"，以便第一次使用时知道从哪里开始。

## Implementation Decisions

### 1. 页面结构：顶栏换成侧栏，服务端不变

- 页面根布局从"顶栏 + 工作区"改为"左侧栏 + 主列"。主列从上到下是断线提示、执行中提示和现有工作区，工作区里是任务页、子任务详情和成果阅读。
- 删除顶栏、作品选择弹窗和任务选择弹窗。新建作品、新建任务、选择作品、选择任务、创建去重和"确认上次创建结果"的行为全部保留，只是入口换了位置。通用对话框（定稿确认等）保留。
- 侧栏只使用现有状态快照中的作品列表、当前作品的任务摘要、执行中的任务和连接状态。**不改服务端契约，不新增接口。**
  - 状态快照不带每部作品的任务数，作品列表因此不显示其他作品的任务数，只显示当前、执行中和读取错误；
  - 作品卡片上的"N 个写作任务"指当前作品；
  - 状态快照分不出空白任务，所以空闲任务的状态行显示创建时间，不显示"尚未开始"。
- 任务标题上方的"写作空间"改为"作品名 / 写作任务"。

### 2. 侧栏的纯推导

在页面现有的纯推导层旁边新增一组侧栏推导函数，输入是任务摘要列表、当前任务、执行中的任务和连接状态，不访问 DOM 和网络。产出以下内容：

- 每个任务行：名称、状态文字、色调、是否当前、是否在执行（跳动圆点）、是否可点。
  - 状态文字按优先级取一种：读取错误为"记录损坏"；执行中为"执行中"；正在停止为"正在停止"；等待作者决定为"待决定"；失败、中断、停止分别为"执行失败""已中断""已停止"；其余显示创建时间。
  - 色调：执行中为 running，失败为 failed，停止中、停止和中断为 warn，其余为 idle；断线时一律为 offline。
  - 只有执行中的任务与当前执行引用一致、且连接正常时才算在执行。
- 窄栏任务图标的角标：本作品有任务在执行（同上条件）为 running；否则有失败为 failed；都没有则不显示。
- 作品卡片：首字、名称、"N 个写作任务"；没有选中作品时显示"选择作品"。
- 作品列表行：名称、是否当前、是否在执行、读取错误。
- 提示内容：作品卡片为"切换作品"加当前作品名；任务图标为"写作任务"加"N 个 · 当前「任务名」"；新建任务在断线时附"连接恢复后可用"；收起和展开按钮附快捷键。

### 3. 展开、窄栏、抽屉三种形态

- 断点沿用现有的 780px：宽于 780px 为桌面，可在展开（约 252px）和窄栏（约 60px）之间切换；窄于等于 780px 为抽屉（宽 min(280px, 86vw)），默认关闭。
- 所有行共用同一列 40px 的图标槽，窄栏中心位置与展开时一致。收起时只裁宽度、文字淡出，不重排；宽度变化约 280ms。页面首次渲染完成后才启用宽度动画，避免按保存状态初始化时播放动画。
- 窄栏中各控件的行为：
  - 品牌位变为展开按钮，收起按钮隐藏且不可聚焦；
  - 作品卡片只留封面，作品列表改为在侧栏右侧弹出；
  - 任务列表隐藏，任务图标变为可聚焦按钮，点开在侧栏右侧弹出任务列表，底部有"新建任务"；
  - 展开状态下任务图标只是不可聚焦的分区标题。
- 弹出的作品列表和任务列表是非模态浮层：Escape、点外部或再次点击触发按钮都会关闭，关闭后焦点回到触发按钮。切换形态、切换任务或作品时自动关闭。
- 提示浮层仅在桌面上出现：
  - 窄栏状态下对所有图标生效；展开状态下只对收起按钮和被截断的任务名生效；
  - 悬停约 420ms 后出现，提示刚消失后约 350ms 内移到下一个图标会立即出现；
  - 键盘聚焦（focus-visible）时立即出现；按下鼠标或离开侧栏即隐藏；
  - 对应的弹出列表打开时，不再显示该按钮的提示。
- 快捷键 ⌘\（非 Mac 为 Ctrl+\）：桌面上切换展开和窄栏，窄屏上开关抽屉。焦点在侧栏内时，切换后把焦点移到新形态下对应的展开或收起按钮。
- 抽屉：
  - 打开时显示遮罩，焦点进入抽屉；
  - 点遮罩、点关闭按钮、按 Escape 或选择任务都会关闭，关闭后焦点回到任务标题旁的打开按钮；
  - 抽屉关闭时侧栏整体不可交互（inert）；窄屏全屏阅读成果时侧栏同样不可交互。
- 视口跨过断点时，按新形态重新渲染，关闭抽屉、遮罩和弹出列表。

### 4. 本机保存

- 窄栏和展开的选择保存在本机，是全局偏好，不按作品或任务区分。这与现有按"作品 + 任务"保存输入和阅读位置的做法分开存放。
- 抽屉开合不保存，窄屏每次进入都默认关闭。
- 本机存储不可用时默认展开，不报错。

### 5. 刷新与稳定

- 侧栏随现有轮询更新。只有任务行、角标、作品卡片或连接状态的推导结果真正变化时，才更新对应节点。
- 更新时保留任务列表的滚动位置、当前焦点和打开的弹出列表，不能重新引入此前信息流计时导致的整段重绘抖动。

## Testing Decisions

- 好的测试只验证作者看得到的行为：给定任务摘要和连接状态，侧栏显示什么、能点什么；给定操作，形态和焦点怎么变。不断言 CSS 类名、内部状态字段或私有函数。
- **主测试接口：页面纯推导层的侧栏推导。**沿用现有推导层测试的做法，用 node 内置测试直接喂入任务摘要样例。覆盖：
  - 状态文字的全部优先级分支，包括记录损坏、待决定与执行中同时出现的情况；
  - 色调，以及断线时一律 offline；
  - 跳动圆点只给与执行引用一致且已连接的任务；
  - 窄栏角标：执行中优先于失败，断线不显示执行中；
  - 作品卡片的任务数和未选择作品时的文案；
  - 提示内容和断线时新建任务的附注。
- **服务端不新增测试。**本规格不改契约，现有本机应用测试和写作任务测试继续保证任务摘要、创建去重和切换的正确性，须保持通过。
- **验收证据：浏览器走查。**沿用《查看 Agent 执行过程》一轮的脚本化本机服务，在真实页面上走一遍，截图和文字输出保存到本功能的 `evidence/` 目录。覆盖：
  - 桌面展开、窄栏、窄栏提示、窄栏弹出任务列表与角标；
  - 快捷键切换、刷新后保留收起状态、首次加载无动画；
  - 从侧栏切换任务后输入与阅读位置按任务恢复；
  - 另一条任务执行中时侧栏状态；断线时侧栏状态与新建任务禁用；
  - 窄屏抽屉的打开、遮罩关闭、Escape、选择任务后关闭、焦点返回；
  - 窄屏无横向溢出；视口跨断点切换。
- 先例：现有推导层测试（动作摘要、子任务入口文案）、子任务进度的浏览器走查脚本，以及写作任务一轮的浏览器检查脚本。

## Out of Scope

- 改服务端状态快照或接口，例如给作品带任务数、给任务带"尚未开始"标记。
- 任务的重命名、删除、归档、置顶、搜索或拖动排序。
- 作品的重命名、删除和封面图片；封面只用作品名首字。
- 跨作品的任务总览。
- 拖动调整侧栏宽度。
- 侧栏里显示子任务；子任务仍只在信息流卡片、子任务入口和详情面板里出现。
- 深色模式和新的设计 token；沿用现有 token。

## Further Notes

- 原型地址后加 `?scenario=offline|empty` 可以查看断线和空作品下的侧栏。原型同时演示了收起动画、提示和窄屏抽屉的细节，实现时以它为视觉对照。
- 原型中的作品列表为每部作品显示任务数，这依赖状态快照没有的数据，本规格明确不做（见实现决策第 1 节）。
- 本规格与《查看 Agent 执行过程》在任务页上的改动不重叠：后者负责信息流、卡片、子任务入口、详情和输入区，本规格只改页面外框、作品与任务的入口和任务标题上方的位置信息。
