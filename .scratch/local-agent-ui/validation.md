日期：2026-10-04。实现基于规格 `3b01221`，首个实现提交 `22d384e`；后续提交包含评审修复、恢复和完整验收。本记录区分可控模型测试、真实浏览器及真实模型，原型演示不计入结果。

## 运行

在 `v0/` 执行 `npm ci && npm run build && npm start`，打开终端显示的回环地址（默认 `http://127.0.0.1:4317`）。开发和配置说明见 [本机写作空间](../../docs/local-agent-ui.md)。

本次环境：macOS，Node `v26.5.0`，npm `11.17.0`，Playwright Chromium。前端使用原生 TypeScript/CSS，没有新增 npm 依赖。凭证和模型配置留在服务端。

## 浏览器走查

在真实本机服务和下述真实验收作品上操作页面：

- 1440×960 并排阅读、390×844 全屏阅读均无横向溢出；正文只读，版本及检查结论明确。
- 阅读开关、引用版本、定稿确认、作品选择、整体停止均通过可见按钮完成。窄屏阅读隔离背景焦点；Escape 关闭后回到原稿件卡片；作品浮层关闭后回到切换按钮。
- 同一浏览器中切换 A/B、刷新、离线/重连后，未发送输入仍属于原作品。运行中的 A 在 B 页面有返回和停止入口，B 发送被禁用，服务端竞争测试也拒绝 B。
- A 停止完成后可启动 B；随后从页面停止 B，两个任务均为 `stopped`，服务占用为 `null`，已保存正文及资料仍在。
- 轮询保留消息节点、输入和正文滚动位置；执行详情不因状态更新折叠。减少动态效果时无运行中的动画。
- 页面无 JavaScript 异常。断网走查只有预期的 `ERR_INTERNET_DISCONNECTED` 请求错误，恢复联网后自动恢复连接显示。

## 真实模型旅程

使用现有 OpenAI 登录；四个角色均为既有配置中的 `gpt-6.1-sol / xhigh`。没有修改模型、thinking、凭证或计费来源。所有新作品隔离在临时目录：

`/var/folders/vj/95373mq10c313_bw3k6g8kkw0000gn/T/noya-ui-live-9G8axD`

验收入口为 `node test/manual-live.ts`，重启通过 `NOYA_ACCEPTANCE_ROOT` 指向同一目录。A 为 `w2aa57b97 / t7b0fc1f2`，B 为 `wc67069e2`。可复核的无凭证摘要见 [live-result.json](evidence/live-result.json)。

1. 在空白页讨论“旅人雨夜进入旧驿站，掌柜正在等他”。Context 区分建议与未知，只讨论，未派写手、未写正式资料。
2. 明确要求约 500 字《雨夜留灯》。Context 保存材料、派 Writer、检查方案并自动批准正文；Writer 提交初稿，独立 Reviewer 检查。作者没有点击方案批准按钮。
3. Context 采纳说话者歧义的措辞建议，保存第二版并派新 Reviewer。检查员留下“方案先行流程”的核实项，Context 回查实际方案记录后说明已核实；页面仍如实保留核实记录，没有伪造“四项通过”。
4. 页面引用第二版，仅要求“旅人顶着夜雨”改为“旅人冒着夜雨”。第三版经新 Reviewer 检查后交稿。直接比较文件确认，第三版恰好等于第二版做这一个替换，旧稿均保留。
5. 重启服务后从页面阅读并选择较旧的第二版定稿。实际正式正文来自第二版；第三版没有被误选。Context、Sync Checker 完成两个人物、大纲节点和章节摘要写入，待同步清空。
6. 从页面将第三版替换定稿。确认框明确替换既有正式正文。正文保存、登记待同步后立即停止服务，再重启。页面显示服务恢复通知，旧 Agent 标为中断；Context 从材料重新安排核对，只补回该次定稿清空的章节元数据，没有重新定稿或改动正文。
7. 重启后的同步实际完成，待同步清空；正式正文与第三版一致。登记中只有两次作者明确定稿，分别指向第二、第三版，没有重启造成的重复定稿。
8. 在 A 发起一次仅讨论的执行，切到 B 保留输入并刷新，从 B 停止 A。确认真正停止后，在 B 启动讨论并停止。最终两部作品均停止，无后台模型工作继续占用。
