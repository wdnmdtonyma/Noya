# Noya 本地 Agent 任务界面 MVP

Status: ready-for-agent

日期：2026-10-04。设计基线：作者已确认的六段用户旅程与收敛后的可点击页面。首位用户是作者本人；本期交付本机启动、浏览器使用的真实应用。

## Problem Statement

作者已跑通 Noya v0，并接入了 OpenAI 能力，但通过命令行讨论写作、查看正文、反馈修改和继续任务不方便。作者需要在一个页面里完成日常写作，不必到命令行或文件目录中寻找交稿。

作者同时拥有多部作品。页面必须让作者明确自己正在查看哪部作品、哪一版稿件，以及当前执行属于哪部作品；切换与重新打开不能混入另一部作品的对话、资料或未发送输入。

作者需要的是 Agent 任务界面。正文由 Agent 生成和修改，作者负责提出意图、阅读和作出必要决定。首版不需要正文编辑器，也不需要把 v0 的所有工具都变成独立页面。

## Solution

提供一个本地任务页面：顶部选择或新建作品，中间与 Context Agent 对话并查看实际执行进展，从交稿消息打开只读正文，读完在同一任务中提出修改或明确将该版本定稿。

保留现有四个角色的分工。Context Agent 是唯一与作者对话的 Agent；Writing Agent 负责章节方案与正文；正文检查员检查指定版本；同步核对员核对定稿正文带来的资料变化。章节方案由 Context Agent 检查，正常流程自动推进，只有确实需要作者决定时才打断。

每部作品分别保留自己的任务、产物与输入。首版同一时间只执行一个作者任务，运行中仍可查看另一部作品；切换不取消原任务，也不启动新执行。关闭页面后重新连接本机服务，恢复真实状态；本机程序退出后恢复已保存记录，如实说明执行中断。

成功标准是：作者在真实页面中进入或新建作品，完成“讨论 → 明确要求写作 → 阅读初稿 → 提一次修改 → 阅读新稿 → 指定版本定稿 → 资料同步”，切到另一部作品并返回，关闭后还能继续原来的工作。

## User Stories

1. 作为作者，我想在自己的电脑上启动 Noya 并打开浏览器页面，以便使用已有模型配置开始写作。
2. 作为作者，我想已有配置可用时直接进入作品，以便每次使用不必经过重复设置。
3. 作为作者，我想没有作品时看到开始第一部作品的入口，以便从零开始。
4. 作为作者，我想新建作品后直接描述想法，以便不必先填写书名、题材或设定表。
5. 作为作者，我想新作品具有可区分的默认名称，以便在多部未命名作品之间识别当前对象。
6. 作为作者，我想只有一部作品时直接回到它的最近任务，以便减少进入步骤。
7. 作为作者，我想拥有多部作品时默认回到上次作品，以便延续此前工作。
8. 作为作者，我想上次作品不可用时能够选择其他已有作品，以便不会被失效记录阻挡。
9. 作为作者，我想进入尚无任务的已有作品时得到空白起点，以便正常开始讨论。
10. 作为作者，我想始终看见当前作品标识，以便知道输入和稿件属于哪里。
11. 作为作者，我想通过轻量入口切换或新建作品，以便不必进入独立管理页面。
12. 作为作者，我想先讨论想法而不自动开始写稿，以便逐步形成方向。
13. 作为作者，我想查询作品已有内容时区分正式事实、未来计划、建议与未知，以便据此作创作决定。
14. 作为作者，我想写入正式资料前看到具体变更并明确确认，以便讨论中的试探和废案不被当作定论。
15. 作为作者，我想明确要求写作后只补充影响故事走向的关键决定，以便无需为非关键细节填写完整表单。
16. 作为作者，我想 Writing Agent 只收到我认可的本章要求和相关材料，以便旧方案与完整讨论不会污染正文。
17. 作为作者，我想上一章资料尚未同步时先完成同步，以便新章节使用最新依据。
18. 作为作者，我想 Context Agent 自动检查章节方案并推进写作，以便不用逐章审批内部步骤。
19. 作为作者，我想真正涉及创作分歧时收到清楚的问题，以便保留对关键方向的决定权。
20. 作为作者，我想看见实际执行进展，并按需展开角色记录，以便知道当前在准备、写作、检查还是同步。
21. 作为作者，我想每份交稿附带对应版本的检查结论，以便理解它是否仍有问题。
22. 作为作者，我想明确冲突在交稿前被处理，无法修好的问题被如实说明，以便避免无限等待或误以为全部通过。
23. 作为作者，我想从交稿消息打开完整正文，以便不用寻找本地文件。
24. 作为作者，我想正文以只读形式呈现，并清楚标出作品、章节与版本，以便专注阅读且不会改错对象。
25. 作为作者，我想阅读时方便返回同一任务提出意见，以便不中断修改流程。
26. 作为作者，我想修改意见明确关联我正在阅读的版本，以便 Agent 不会误改另一份稿件。
27. 作为作者，我想纯措辞修改由 Context Agent 完成并保存新版本，以便快速修正表达。
28. 作为作者，我想沿原方向的修改交给原 Writing Agent，并带上更新后的要求，以便延续已有创作思路。
29. 作为作者，我想推翻关键方向时先确认新方向，再由新 Writing Agent 重写，以便摆脱旧方案影响。
30. 作为作者，我想写作过程中也能补充意见，以便及时调整正在进行的工作。
31. 作为作者，我想修改后的正文由新的正文检查员复查，以便检查与新版本对应。
32. 作为作者，我想新稿交付后仍能从原消息阅读旧稿，以便找回此前内容。
33. 作为作者，我想对正在阅读的明确版本定稿，即使它不是最新版，以便由我选择最终接受的正文。
34. 作为作者，我想定稿前确认作品、章节和版本，以及是否替换已有正式正文，以便避免误操作。
35. 作为作者，我想正文保存成功后立即看到已定稿，以便资料同步不会阻挡正文被接受。
36. 作为作者，我想定稿后自动开始资料同步，以便不用手动指挥各个 Agent。
37. 作为作者，我想只有定稿正文实际支持的变化进入资料，以便被删除的初稿内容不成为正式事实。
38. 作为作者，我想资料冲突一次列明双方依据并由我决定，以便保留对作品设定的控制。
39. 作为作者，我想能够保留某项原设定，同时完成其他有依据的同步，以便一个被拒绝的变化不会让整章永久卡住。
40. 作为作者，我想同步失败时仍看到正文已定稿和资料待同步两个状态，以便知道什么已经保存、什么还需处理。
41. 作为作者，我想恢复同步时沿用已定稿正文和已有结果，以便不用重新定稿或重新写章。
42. 作为作者，我想 A 作品执行时仍能查看 B 作品，以便等待期间阅读其他内容。
43. 作为作者，我想查看 B 时明确知道 A 仍在执行，并能返回 A，以便不会误以为任务已停止。
44. 作为作者，我想 A 执行期间 B 不会开启另一项执行，以便首版保持一次一个作者任务。
45. 作为作者，我想可以明确停止 A 的整体执行，实际停止后再开始 B，以便控制当前工作。
46. 作为作者，我想停止保留已保存对话与产物，并说明停止结果，以便稍后继续。
47. 作为作者，我想切换回来时恢复该作品自己的对话、稿件和未发送输入，以便不同作品互不混淆。
48. 作为作者，我想仅关闭或刷新页面时重新连接仍在运行的本机服务，以便无需重新发起同一任务。
49. 作为作者，我想程序退出后看到恢复记录和真实的中断状态，以便不误以为旧 Agent 仍在执行。
50. 作为作者，我想原 Writing Agent 已不可恢复时由 Context Agent 根据保存材料重新安排并告知我，以便继续修改。
51. 作为作者，我想模型、连接或保存失败时看到原因、已有成果和下一步，以便处理后继续且不把失败当作成功。
52. 作为作者，我想在较窄窗口和使用键盘时仍能切换作品、阅读和关闭浮层，以便页面适应日常使用方式。

## Implementation Decisions

### 1. 复用 v0，增加本地页面接入

- 沿用现有共享 ModelRuntime、openWritingSession、TaskHub、角色工具、提示词及 Skills。新增的本机应用适配层负责作品入口、页面命令、状态查询和运行生命周期，集中形成一个供页面使用的边界。
- 不在浏览器重建 Agent 编排。页面根据真实模型文本、执行事件、任务记录和产物呈现状态；不得用原型的计时器、关键词分支或固定样稿替代实际执行。
- 先提供一个本机服务和同源页面，默认仅监听回环地址。现有模型配置、登录和凭证继续由既有运行时管理；浏览器不接收凭证，不接受任意文件路径作为作品或产物读取接口。
- 已配置的作者直接进入工作。未登录、配置不完整或模型不可用时提供具体阻挡原因和现有配置方式的指引，保留已保存内容；本期不增加模型或账号设置页。
- 保持 CLI 入口可用。页面的作品切换由应用适配层选择作品及其任务完成，不通过绕过现有 Pi 会话切换保护来实现。

### 2. 作品入口与任务恢复

- 从配置的本机作品范围发现有效作品。使用稳定作品身份，补充最少的显示名与最近访问记录；不搬迁已有作品，也不改变正式内容的存储格式。没有名称时提供稳定、可区分的回退名称；名称不是创建前置条件。
- 无作品时显示空白入口；单作品进入其最近任务；多作品恢复有效的上次作品，否则显示选择入口。已有作品没有任务时创建首个任务，不能直接把“找不到最近任务”的异常显示成不可使用。
- 进入页面、刷新、切换和普通发送不各自创建新任务；默认恢复该作品的最近任务。按现有任务记录定义选择最近任务，不新增历史任务管理或任务分叉界面。
- 正式资料、任务记录、产物和运行时会话沿用现有持久化；浏览器只保存当前作品、每部作品的未发送输入及阅读偏好等界面状态，不能成为业务结果的唯一来源。
- 缺失或损坏的记录需说明受影响对象；不能静默创建同名替代作品或丢弃已有记录。

### 3. 一个任务空间，按需打开阅读空间

- 沿用已认可的页面组织和视觉变量：顶部作品入口，主要区域为最近任务的对话、执行摘要和输入区。执行详情按需展开，显示 Context Agent、Writing Agent、正文检查员、同步核对员实际参与的工作。
- 正文从对应交稿消息打开。桌面支持阅读与任务并排；窄屏使用可关闭的阅读层。正文不可直接编辑，明确显示作品、章节、版本及是否已定稿。
- 各版本是保存后的独立产物，旧消息仍可打开旧稿。检查结论、修改引用与定稿对象必须关联同一份明确稿件，不能用“最新版”替代作者选择。
- 方案、检查和同步结果作为任务记录及必要的摘要呈现，不增加独立管理页。无需向作者展示内部提示词、原始工具参数或文件路径才能理解任务。
- 键盘可访问主要操作，浮层关闭后恢复焦点；窄屏阅读时底层任务区不能获取焦点，遵守减少动态效果设置。

### 4. 页面与本机服务的行为契约

| 行为 | 输入与服务端责任 | 可观察结果 |
| --- | --- | --- |
| 进入或切换作品 | 校验作品身份，读取最近任务及产物；查看不会启动模型执行 | 当前作品的快照、记录与真实执行状态 |
| 新建作品 | 创建独立作品和首个任务；不要求名称表单，不自动调用模型 | 可输入的空白任务与可区分的作品标识 |
| 发送或补充意见 | 明确作品、任务、作者文本；可带已保存稿件引用；校验归属和运行占用 | 作者消息被接受或明确拒绝，随后收到对应任务的回复与进展 |
| 回答具体决定 | 绑定具体提问及其对象、选项或作者文本；保存真实作者回答 | Context Agent 处理此决定；过期或已处理的决定不会应用到其他对象 |
| 读取正文 | 校验作品、任务、稿件身份，只读取完整的已保存产物 | 对应版本全文及其检查、定稿状态 |
| 定稿 | 必须显式指定稿件身份，并包含作者针对该对象的确认；校验最新状态 | 正式章节保存结果，以及独立的同步状态 |
| 停止 | 指向明确的运行中作品与任务，覆盖 Context 及其正在执行的子 Agent | 先显示停止中，确认实际结束后显示已停止 |
| 继续处理 | 在单任务限制下，把作者继续意图交给 Context；依据已保存结果重新安排 | 新一轮实际进展，不把旧子 Agent 显示为自动复活 |
| 重连 | 重新读取任务快照、已保存消息及产物，再接收增量变化 | 补齐离线期间变化，不重复显示消息或重新执行已接受的指令 |

- 所有变更请求在服务端校验，禁用按钮不是业务门禁。作品、任务和产物身份共同限定操作对象，拒绝跨作品引用和无效身份。
- 增量更新携带所属作品、任务及足够的消息或产物身份，避免切换后把迟到事件插入当前作品。具体传输方式由实现选择；无需自建持久化事件总线。
- 接受请求与执行完成分开表达；正文未保存、检查未完成或写入失败时不能提前显示成功。断线导致结果未知时先重新读取服务端结果，不盲目重发写作、定稿或确认请求。
- 重复点击、重连与同一服务的多标签页不能导致重复执行或重复定稿；以已有任务、产物和最新领域状态核验，不新增通用操作级恢复框架。
- 作者确认必须进入所属任务的真实作者记录，并保留被确认内容及引用。不能由前端生成一个脱离上下文的“同意”，也不能让模型代替作者完成定稿。

### 5. 讨论、写作与检查

- Context Agent 负责区分讨论、查询、正式资料写入与写作意图。普通讨论不自动派 Writing Agent；正式资料写入保留现有作者确认门禁。
- 准备写作时，先解决会改变关键方向的缺口，并处理当前作品的待同步章节。只把作者接受的要求写入 Writing Brief，与相关 Context Pack 组成 Writing Package。
- Writing Agent 仅接收 Writing Package，不接收完整作者对话、废案或原始检索过程。先交章节方案，Context Agent 检查通过后自动要求写正文。
- 正文检查员每轮使用新的会话，输入限定为相应 Writing Brief、Context Pack 和明确版本正文。Context Agent 核实待核实项，将有依据的冲突反馈给 Writing Agent；编辑建议本身不阻断交稿。
- 沿用已确认旅程与当前写章 Skill 的返修停止条件：四项质量门禁全部通过；同一冲突按“同一门禁项及同一依据来源”连续两轮未解决；或可比较的相邻轮次中冲突数量没有下降。满足任一条件后停止自动返修并交付检查结论、剩余冲突与待决定问题。首次检查没有上一轮时不使用数量比较条件。
- 交稿、检查通过和作者定稿是不同事实。Agent 或其某一轮变为空闲不等于整个写作任务已完成，已存在稿件也不等于它已完成检查。

### 6. 修改与明确版本定稿

- 从阅读空间提出修改时带上所读稿件引用，并在输入区可见。版本显示序号只用于作者识别，服务端以产物身份解析实际正文。
- 纯措辞修正由 Context Agent 保存新修订；沿原方向的局部修改交给原 Writing Agent，要求变化时同时更新 Writing Brief；结构性重写先确认新方向，再用更新后的 Writing Package 派新 Writing Agent，并停止旧 Writer。
- 中途补充意见沿用上述分类。同一个作者任务内允许经 Context 传递补充要求；不得为此启动第二个作者任务，也不能直接从页面给子 Agent 下达业务指令。
- 原 Writer 已不可恢复时，Context 依据保存的要求、资料和目标稿件重新安排，并向作者说明；不伪造原会话仍在运行。修改后的稿件重新经过正文检查。
- 定稿确认明确作品、章节和所读版本。允许选择较早的完整稿件；页面必须向领域动作传递该稿件身份，不使用默认最新版分支。
- 已有正式章节时，确认文案说明将替换该章节正文，旧稿件仍保留；这是一次新的定稿和同步，不是覆盖旧产物。旧同步清单不能应用到后来重新定稿的正文。

### 7. 定稿与 Context 同步分开

- 作者定稿后复用现有领域动作保存正式章节、登记待同步并记录定稿对象。只有真实保存成功才显示“正文已定稿”；随后通知 Context 开始同步。同步失败不回退正文。
- Context 从定稿正文提出变化并附原文依据，同步核对员只核对支持性与冲突。核对通过的正常变化由 Context 应用；不支持的项目删除或修正，清单内容改变后重新核对。
- 冲突一次列明正文与既有资料依据，由作者选择写入或保留原状。作者要求改变冲突项具体内容时，先生成新清单并重新核对；确认仅对具体内容有效。
- 保留原设定时可排除争议项，继续应用其余符合要求的变化；章级摘要与重要登场角色的同步不可遗漏。只有领域结果确认已移出待同步，页面才显示同步完成。
- 可恢复的同步技术失败沿用现有恢复流程；同步核对员技术失败允许重派一次，仍失败就说明原因并保留继续入口。作者明确停止是整体停止，不得当作技术失败自动重派。
- 本机服务在程序中断后恢复此前执行的任务时，按既有同步约定尝试继续未完成同步，并遵守单任务限制；仅在页面中查看或切换作品不触发这一恢复。等待作者决定或曾被作者明确停止的任务不得自动越过决定或恢复执行。开始下一章前必须处理当前作品的待同步内容。

### 8. 单任务执行、跨作品查看与整体停止

- 本机服务持有一个活动作者任务。占用涵盖 Context 正在处理、子 Agent 执行以及已安排但尚未结束的自动后续工作；同一任务内各角色仍可按现有能力运行，不限制为一次只能有一个 Agent。
- 单任务约束由服务端统一执行，覆盖连接该服务的所有浏览器标签页。范围是一个 Noya 本机服务；本期不增加多个独立 CLI 或服务进程之间的分布式协调。
- 选择作品与占用执行资源分开。A 执行时可以查看或创建 B 的空白入口、阅读 B 的已有稿件、保留 B 的输入；B 的发送、定稿及触发执行的确认暂不可用。页面显示 A 的运行提示、返回入口及明确停止入口。
- A 已交稿、失败、停止，或确实停止自动工作并等待作者决定时，可释放执行占用。A 的未解决决定仍保存；B 在执行时，A 的回答不能启动并行工作。
- 停止覆盖主 Context、运行中的子 Agent 及会立即触发新执行的待送达通知。现有只停止运行中子 Agent 的 stopAll 不足以实现页面承诺，适配层必须补齐整体取消和完成确认。
- 只有整体停止完成后才允许另一任务执行。若停止未完成，继续显示停止中或具体错误；不能因一次请求已发出就宣称已停。已完成并保存的内容不删除，未提交的半份稿件不成为可定稿产物。

### 9. 关闭、重连与进程退出

- 关闭或刷新浏览器不自动停止本机服务中的任务。重连后恢复当前作品及其最近任务，查询实际运行状态和离线期间保存的产物，再更新页面。
- 本机程序退出意味着内存中的执行不再存在。重新打开时复用保存的 Context 记录，保留产物与定稿结果，将旧运行中的子 Agent 如实标为中断或终止；不得继续播放原型式进度。
- 恢复以已有会话、任务登记和产物为依据，由 Context 重新安排后续步骤。无需重建通用工作流状态机，也不承诺对每个模型或工具动作作精确续跑。
- 连接中断、模型失败、停止、等待作者和正文已交付需要区分。错误说明发生环节、已保存内容与可采取动作；不得通过自动换供应方、模型或计费来源掩盖失败。

## Testing Decisions

### 测试边界

作者已于本轮确认：主要在“浏览器页面 → 本机应用适配层 → openWritingSession → 真实工具与本地存储”这一条外部边界验收。自动化只在共享 ModelRuntime 的模型响应边界注入可控返回，复用真实角色会话、TaskHub、资料门禁和产物保存，不为四个 Agent 分别增加一组应用测试接口；最后再进行真实模型验收。

已有临时作品 fixture 可创建独立作品和运行时，并为四个角色注册 faux provider；本次扩展为同一服务下两部临时作品。现有“写作流程”“会话工厂”“产物记录”测试已覆盖工具效果、Writer 输入隔离、版本关联、定稿与同步以及重启；订阅集成测试已有共享运行时与失败流的先例。继续复用这些能力，不复制协议或内部实现测试。

良好的测试从作者行为或公开服务命令进入，断言可见状态、明确产物身份和实际保存结果。不要断言内部调用次数、私有方法、DOM 层级、固定等待时长或正文逐字相同。竞态与错误路径可在同一服务边界直接驱动，以免所有组合都依赖浏览器脚本；页面至少完整走通主线与关键恢复路径。

### 必须覆盖的行为

| 场景 | 必须能观察到的结果 |
| --- | --- |
| 零、单、多作品及失效的上次记录 | 正确进入空白、最近任务或选择入口；无任务的作品可开始；刷新不重复创建任务 |
| 空白讨论、查询与资料确认 | 讨论不生成稿件；回答区分事实与建议；具体确认前正式资料不变，确认后才保存 |
| 正常写作链 | 页面发送要求，真实工具保存 Package、方案、正文和检查；Context 推进方案，作者不用点击批准方案 |
| 返修停止与诚实交付 | 模拟连续检查结果，呈现修订与最终遗留问题；“已交稿”不会被渲染成“全部通过”或“已定稿” |
| 三类修改与中途意见 | 正确关联所读稿件及更新后的要求；纯措辞、原方向调整、结构性重写均保存独立新稿并重新检查 |
| 非最新版定稿 | 已有第二版时选择第一版，实际正式正文与第一版一致；重复提交不重复执行定稿 |
| 定稿后同步成功、失败和冲突 | 正式正文先落盘；失败保留待同步；两种冲突决定都可继续处理，必须包含有效章级元数据 |
| 重新定稿后的旧清单 | 旧清单无法写入新正文所对应的正式资料，页面说明需要重新同步 |
| 运行中 A 切换到 B | B 可查看但不能启动执行；迟到消息仍归 A；返回后 A 记录、B 输入互不串用 |
| 同服务的两个标签页同时操作 | 服务端只接受一个作者任务执行；身份、确认和定稿对象不能被另一标签页的切换改变 |
| 整体停止 | 分别在 Context、Writer、检查、同步阶段停止；实际停稳后 B 才可执行，迟到通知不重新派发工作 |
| 浏览器刷新、断开后重连 | 不重新提交原请求，补齐真实消息与产物，已定稿和待同步状态正确；输入仍按作品保存 |
| 服务退出后恢复 | 旧执行标为中断，已保存数据仍在；继续后产生新执行，未提交的半份稿件不能被定稿 |
| 错误与无效引用 | 模型、保存、连接错误不伪装成功；跨作品或不存在的稿件引用被拒绝，已有正文不受影响 |
| 页面可用性 | 桌面及约 390px 窄屏可完成阅读和切换，无横向溢出；键盘、浮层焦点和减少动态效果可用 |

### 真实模型验收与完成条件

- 使用临时验收作品及现有可用配置，实际完成一次短章流程：讨论、明确写作、自动方案检查、初稿与正文检查、作者阅读后修改、指定版本定稿、Context 同步。确认四个角色确实工作，正式章节和资料实际保存。
- 再创建或进入第二部验收作品，验证运行中切换、回到原作品、仅刷新浏览器，以及停止服务后重新启动并继续。故障、竞争和冲突的组合主要由可控模型测试覆盖，不要求制造真实服务商故障。
- 脚本化模型回复只证明接线与外部状态正确，不能证明模型会在自然对话中遵守 Skills。真实验收需检查关键业务步骤和实际产物；章节质量门禁通过不等于文学质量获作者认可。
- 运行既有类型检查与业务回归，并执行上述新增测试和浏览器走查。记录自动化、浏览器与真实模型结果及未覆盖项；没有完成真实页面与模型验收时，不宣布产品化接入完成。

## Out of Scope

- 托管 Web 服务、跨设备同步、多用户协作、权限体系、账号管理和商业化。
- 多个作者任务并行、跨服务进程协调、后台任务队列或任务调度平台。
- 直接正文编辑器、独立作品管理页、历史任务管理、内容目录、版本管理器、盲比页、审计页和模型设置页。
- 为章节方案增加常规作者审批步骤，或要求新建作品先完成开书表单。
- 重写模型接入、角色业务编排、检索系统、正式内容 schema 或现有凭证管理。
- 通用事件溯源、操作级恢复框架、崩溃后自动复活原子 Agent，以及任意工具动作的精确续跑保证。
- 本次规格之外的文风改造、质量门禁扩展、全书级文学质量承诺或额外写作能力。
- 数据看板、使用分析埋点、独立评审项目，以及原型中的测试场景控制器进入正式界面。

- 作者已确认完整旅程测试边界：真实页面、本机服务与 v0 流程，自动化只替换模型响应，最终进行真实模型验收。
