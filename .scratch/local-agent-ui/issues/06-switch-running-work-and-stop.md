# 06 — 运行中切换作品与整体停止

**What to build:** A 作品执行时，作者可以查看 B 的记录和稿件，明确知道 A 仍在运行；作者可返回 A 或明确停止 A，真正停稳后才在 B 开始执行。

**Blocked by:** 03 — 写一章并阅读交稿。

**Status:** ready-for-agent

**Implementation:** completed · 2026-10-04

对应规格：Noya 本地 Agent 任务界面 MVP；用户故事 42–47，以及同服务多标签页和整体取消边界。基于已有 v0 任务与待同步 fixture 可独立验证各角色的停止，不依赖 05 的定稿按钮；最终组合验收由 07 完成。

- [x] 把正在查看的作品与实际执行所属作品分开；A 执行时可查看或创建 B 的空白入口、阅读 B 已保存的正文并保留 B 输入，切换不启动或取消任务。
- [x] 在 B 显示 A 的真实运行提示、返回和明确停止入口；B 的发送、定稿及会触发执行的确认受服务端阻止，不仅依赖按钮禁用。
- [x] 迟到消息、执行变化和产物仍归属于原作品与任务；切回 A 时展示其正确状态，B 的输入和稿件不被覆盖。
- [x] 单任务占用覆盖 Context、子 Agent 和尚未结束的自动后续工作；等待作者决定且确实无执行时可释放占用，决定仍保存，另一作品执行期间不得通过回答旧决定绕过约束。
- [x] 停止覆盖主 Context、正在运行的 Writer、正文检查员、同步核对员，以及会重新启动任务的待送达通知；不把现有仅停止子 Agent 的 stopAll 直接当作整体停止。
- [x] 停止请求明确目标作品与任务，先显示停止中；实际停止确认后才释放占用。停止失败时如实说明，不能提前允许 B 启动。
- [x] 停止后保留已保存对话、稿件及定稿状态；未提交的半份稿件不可定稿。后到的通知不得自动重派 Writer 或同步核对员；修正与整体停止冲突的 Skill 表述。
- [x] 同一服务的两个标签页竞争发起或停止时仍只允许一个作者任务执行；另一标签页的作品切换不能改变操作目标。
- [x] 通过实际页面验证 A 运行、查看 B、返回 A、停止 A 后启动 B；用现有模型响应边界控制时机，在同一本机服务边界验证各角色停止、迟到通知与竞争，不另建内部测试接口。
- [x] 作品切换浮层、运行提示及停止确认支持键盘和窄屏；现有业务回归与类型检查通过。
