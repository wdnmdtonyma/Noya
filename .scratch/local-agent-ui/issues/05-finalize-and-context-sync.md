# 05 — 指定版本定稿并同步资料

**What to build:** 作者明确接受正在阅读的某一版正文，页面先确认正式章节已保存，再展示 Context 同步；有冲突时作者决定，失败时保留定稿并可继续处理。

**Blocked by:** 03 — 写一章并阅读交稿。

**Status:** ready-for-agent

对应规格：Noya 本地 Agent 任务界面 MVP；用户故事 17、33–41。可用已保存的多版本稿件独立验收，因此不以 04 为阻塞项。

- [ ] 定稿确认清楚标出作品、章节和所读版本；作者可以选择较早的完整稿件，实际保存对象必须是明确选定的稿件，不能使用默认最新版。
- [ ] 已有正式章节时说明将替换该章正文，旧稿件仍保留；无效引用、过期对象与重复提交不能产生错误或重复定稿。
- [ ] 复用现有作者定稿动作保存正式章节并登记待同步，真实保存成功后立即显示正文已定稿，再通知 Context 开始同步；同步失败不回退正文。
- [ ] Context 只从定稿正文提取变化和原文依据，同步核对员只核对；支持的正常变化自动应用，不支持的项目删除或改正，清单改变后重新核对。
- [ ] 冲突一次列明正文与既有资料，作者可决定写入或保留原状；真实回答及具体对象进入任务记录。作者改写清单内容时先重新核对，旧确认不能授权新内容。
- [ ] 保留原设定时排除争议项，仍能同步其他有依据的内容及必需的章节摘要、重要登场角色；只有领域结果确认移出待同步才显示完成。
- [ ] 技术失败允许按现有规则恢复，同步核对员最多重派一次后说明失败；正文保持定稿，提供继续同步入口，当前作品下一章写作必须先处理待同步内容。
- [ ] 作者明确停止不属于可自动重试的技术失败；整体取消由 06 提供，本票不得引入会无条件重派被停止任务的恢复逻辑。
- [ ] 重新定稿后旧同步清单不能应用到新的正式正文，界面说明需要重新同步。
- [ ] 使用真实页面、领域写入与临时作品验证指定旧稿定稿、替换定稿、重复请求、同步成功、两种冲突选择和失败后继续；核对实际正式正文与资料，保持单任务服务端约束。
- [ ] 桌面和窄屏的确认及冲突交互可用；现有定稿、资料门禁、产物记录回归和类型检查通过。
