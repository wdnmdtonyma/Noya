# 04 — 针对明确版本修改并复查

**What to build:** 作者读稿后在同一任务中提出意见，Agent 针对所读版本修改、重新检查并交付新稿；作者仍能阅读旧稿，也能在执行中补充要求或确认改变方向。

**Blocked by:** 03 — 写一章并阅读交稿。

**Status:** ready-for-agent

对应规格：Noya 本地 Agent 任务界面 MVP；用户故事 26–32、50。跨进程恢复的组合验收由 07 完成。

- [ ] 从正文提出修改时，输入区显示所引用的章节和版本；发送携带明确作品、任务及稿件身份，不能在后台替换成最新版。
- [ ] 纯措辞修正由 Context 保存新的正文产物；沿原方向的局部修改交给原 Writing Agent，要求变化时更新 Writing Brief；两条路径均保留旧稿。
- [ ] 推翻关键事件、人物动机或揭示方向时，先复述并确认新方向，再保存新 Writing Package、停止旧 Writer 并派新 Writer 走方案与正文流程。未确认或取消时不重写。
- [ ] 写作中补充意见仍经 Context 分类与传递；修改字数不决定是否结构性重写，不因此启动第二个作者任务。
- [ ] 原 Writer 已终止或不可恢复时，Context 根据保存材料和目标稿件重新安排，并说明实际情况；不把历史会话当作仍运行的 Writer。
- [ ] 每份新稿保存为独立产物，重新经过正文检查与既有返修规则；版本身份、使用的要求与检查结果保持关联。
- [ ] 原消息仍可打开旧稿；修改失败时保留旧版本及输入，清楚说明本轮未完成，不用失败结果覆盖成功产物。
- [ ] 验证纯措辞、局部修改、结构性重写、中途意见、不可恢复 Writer，以及“已有第二版却针对第一版提出修改”；通过真实页面与工具核对版本归属和保存结果。
- [ ] 正文只读、窄屏阅读及键盘返回输入区继续可用，既有写作主线和类型检查通过。
