# 01 — 搭好本地应用框架与页面骨架

**What to build:** 作者可以在本机启动正式应用，在浏览器打开沿用已确认设计的任务页面骨架，并看见页面与真实本机服务的连接结果。交付前端、本机服务、最小通信契约、开发与运行命令以及冒烟验证，使下一张票可以直接接入作品和 Context 对话。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

对应规格：Noya 本地 Agent 任务界面 MVP；实现决策 1、3、4。此票是用户追加的首张前置票。

- [ ] 在现有 Node/TypeScript 工程基础上落地前端与本机服务的运行组织，记录实际采用的框架、职责边界及开发、构建、启动和验证命令；从干净安装状态可按说明启动。
- [ ] 一次启动可访问同源页面与服务，默认仅监听回环地址；保留已有 CLI 的使用方式与配置兼容性。
- [ ] 页面实际请求服务并显示连接成功；服务不可达或返回错误时显示真实的连接问题，不用固定“已连接”文案代替通信。
- [ ] 页面骨架复用已认可的视觉变量和任务布局，为作品入口、任务空间与按需阅读留下位置；暂未接入的操作不伪装可用，不搬入演示样稿、演示计时器和测试场景控制器。
- [ ] 建立最小的请求、响应与错误契约，后续作品及任务能力从同一本机应用边界扩展；不新建通用事件平台或复制 Agent 编排。
- [ ] 运行配置与凭证留在服务端，浏览器资源和连接响应不包含秘密；页面骨架无需模型登录即可打开，也不会调用模型或创建、修改真实作品。
- [ ] 若入口与 CLI 初始化耦合妨碍页面启动，先做保持原行为的最小整理，再接页面；复用现有业务入口，不进行无关重构。
- [ ] 在独立测试环境中启动真实服务，通过浏览器打开页面，验证连接成功和连接失败两个可见结果；现有类型检查与相关 CLI 回归通过。
- [ ] 桌面及约 390px 窄屏下骨架无横向溢出，主要占位与连接状态可读，基本键盘操作可用。
