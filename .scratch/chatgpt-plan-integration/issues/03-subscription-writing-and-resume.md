# 03 — 四角色共享订阅完成短章与重启续写

**What to build:** 作者用一个 ChatGPT 订阅账号、一个实际可用的模型完成一条短章流程：Context Agent 准备 Writing Package，Writing Agent 交章节方案和初稿，正文检查员检查，作者定稿后由同步核对员参与 Context 同步。退出并继续写作任务后，订阅授权、对话和产物仍能使用。

**Blocked by:** 02 — 用 ChatGPT 订阅完成 Context 交互与工具调用。

**Status:** ready-for-agent

- [ ] 四个角色共用同一订阅授权与 ModelRuntime，可按既有配置选模型；角色并发时不会各自登录或创建凭证副本。首次真实验收使用同一个已验证可调用的模型。
- [ ] 现有应用层 fixture 驱动完整写作流程，确认 Writer 只接收 Writing Package、正文检查员独立运行、作者决定定稿、同步只依据定稿正文，失败轮次与已完成产物状态正确。
- [ ] 退出后按既有入口继续任务，恢复原对话、任务登记、工具调用历史和产物；再次请求使用 Pi 保存的订阅凭证，不静默换模型或改用付费 API key。
- [ ] 在独立测试作品中由作者通过浏览器授权 Pi，先完成一条极小请求，再实际完成章节方案、短初稿、正文检查、作者定稿和 Context 同步；最后重启续写并完成下一条请求。
- [ ] 留下脱敏验收结果：依赖版本、模型、完成事件、工具／产物结果及续写结果。不记录 token、完整回调 URL 或含 token 的授权 URL，不把 API 价格估算当作实际订阅扣费，也不把文学质量列为此次接入验收结论。
- [ ] typecheck 与相关行为回归通过。模拟验证与真实订阅验收分别报告；真实验收尚未完成时明确记录待完成，不把该票标为已交付。
