# 01 — 主信息流显示 Context Agent 的完整过程

**What to build:** 作者在任务页能看到 Context Agent（界面显示为 Main）的完整可见过程，不再只看到文字回复和一句改写过的动作提示：
- 文字消息直接显示，并在流式输出时更新。
- 相邻的思考与工具调用合成一组，默认收起，收起时只显示一句"动作 + 对象"摘要。
- 展开后按发生顺序逐行列出每一步，每行可以再展开，查看原工具名、完整参数、最终返回和错误。

这是后续所有工单的地基，包含两部分：
1. 任务视图扩展：从已保存的 Context Agent 会话读出工具调用与思考，归一化成通用的过程项。
2. 页面的纯推导层：把任务视图变成展示模型，不依赖 DOM，带 node 测试。

不新增平行的事件存储。规格见 `.scratch/subagent-progress/spec.md`（实现决定 1、3、4）。

**Blocked by:** None — can start immediately

**Status:** ready-for-human

- [x] 任务视图按时间返回 Context Agent 的过程项：
  - 消息；
  - 思考（可读的给出原文，redacted 的标为不可读）；
  - 工具调用（原工具名、完整参数、返回、错误标记）；
  - 未知内容（保留类型与原文）。
- [x] 原有的作者和助手消息身份与顺序不变；页面注入的作者提示仍被过滤；原有字段保留，CLI 照常可用。
- [x] 多次读取同一任务时，每条消息和每个调用的身份保持稳定。
- [x] 动作摘要按规格规则生成，不显示步数和调用次数：
  - 文件类动作按文件名归并；
  - 已知的 Noya 工具使用固定短语；
  - 未知工具显示原名；
  - 超过 3 项时显示前两项加"等 N 项"；
  - 失败写成"修改 x 失败"并排在最前；
  - 返回无改动时写成"未改动 x"。
- [x] 摘要不依据 Agent 的业务角色。
- [x] 常规的开始和结束、停止请求、Context Agent 自身的错误和中断事件不单独成行；作者定稿等非常规事件在原位置保留一行。
- [x] 本机应用测试（测试替身模型）覆盖：过程顺序、内容完整、身份稳定。
- [x] 纯推导层的 node 测试覆盖全部摘要规则；原型的固定样例改写为测试数据。
