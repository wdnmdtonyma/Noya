# 02 — 子任务卡片与每次执行的成果

**What to build:** Context Agent 每派发一个 Sub，或给 Writer 追加要求，信息流对应位置出现一张子任务卡片，作者不打开详情就知道交给了谁、做出了什么：
- 标题是 Context Agent 派发时写的一句任务说明，最多两行；Sub 身份作为次要信息。
- 追加要求的卡片标为"追加要求 · writer-1"。
- 状态使用全页统一的说法：进行中、正在停止、已交回、已回复、未交回成果、失败、已停止、已中断。
- 卡片只挂这一次执行交回的成果，每份一行，带标题和一句说明，点"阅读"可以打开。检查报告的说明行直接写结论。
- 右上角常驻"过程 ›"。

规格见实现决定 2、3。

**Blocked by:** 01 — 主信息流显示 Context Agent 的完整过程

**Status:** ready-for-human

- [x] 每次派发或追加要求的调用，按发生顺序与该 Sub 的下一条执行记录配对。
- [x] 配对失败时，卡片仍显示这次调用并标明缺失，不猜测归属。
- [x] 结果判定集中在服务端一处，覆盖：
  - 已交回、已回复（附 Sub 的最后一句话）、未交回成果；
  - 失败（附错误原文第一行）；
  - 已停止、已中断（说明未收到最终返回）；
  - 执行结果为 retired 的，归入已停止。
- [x] 派发 Sub 的工具增加必填的简短任务说明参数；为空或过长时拒绝，并提示 Context Agent 重写。
- [x] 任务说明保存到该次执行的记录，作为卡片标题显示；**不进入 Sub 的输入**。测试断言 Sub 收到的输入里没有这句说明。
- [x] Context Agent 的系统提示补一条：派发时用作者能读懂的话写这次要做什么，不复述材料。
- [x] 旧执行记录没有说明时，标题显示 Sub 身份并注明"未写任务说明"，不从材料中猜测。
- [x] 追加要求卡片的标题取 Context Agent 给 Writer 的消息原文。
- [x] 同一个 Sub 执行多次时各有一张卡片，较早的版本仍能从它原来的卡片打开。
- [x] 主信息流里没有任何 Sub 的过程项。
- [x] 本机应用测试覆盖：
  - 写手先交方案、追加要求后交正文、检查员交检查结论，每张卡片只挂自己那次的成果；
  - 各种结果的判定。
