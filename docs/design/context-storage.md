# Context 存储与读取

本文件记录已确认的存储和消费方向，细化 ADR 0004；具体索引后端与工具接口尚未选定。内容格式见 [Context 类型定义](context-types.md)，以下 JSON 只示范结构，不限定最终编码。

## 已确认的职责

- 结构化内容文件保存正式资料，索引从这些文件派生，可重建。
- 世界志保持逻辑树形，按通常一起使用的子树分文件；子树内部继续嵌套，跨文件位置通过 `ref_id` 引用。暂不自动按大小拆分，也不强制每个节点一个文件。
- 节点 ID 稳定，文件移动不改变 ID。索引保存名称、摘要、类型、上级路径和文件位置，便于定位与筛选；检索也覆盖详细内容，不能只搜索摘要。
- Context Agent 自己理解自然语言、判断相关性；本地工具只负责确定性的搜索、节点读取、批量读取和子树读取。不增加第三个检索 Agent 或独立自然语言检索服务。
- 程序可以读取并解析整个文件，只向模型返回选中的节点；物理文件大小不等于模型必须接收的上下文量。批量结果应按 ID 去重，避免重叠子树重复返回。
- 保存资料后刷新索引，不能把过期索引当作最新事实。具体新鲜度检查与失败恢复协议仍待实现规格细化；索引不承载作者唯一一份设定。
- MVP 先做本地索引与关键词搜索，SQLite 全文检索或向量检索均非当前必选实现。以旧角色查询、规则查询和章节准备验证调用次数、读入上下文量以及关键事实漏检情况。

## 完整拆分案例

以下三份文件构成一个虚构案例，实际内容节点均包含完整描述字段。Schema 校验前两份内容文件；索引采用不同的派生结构，不作为世界志节点文件解析，其正式 schema 尚待定义。

```text
world/
├── qingyun.json
├── luoxing.json
└── index.json
```

### qingyun.json：青云宗及矿洞引用

```json
{
  "schema_version": 1,
  "nodes": [
    {
      "id": "world_qingyun",
      "kind": "faction",
      "title": "青云宗",
      "summary": "东境修行宗门，控制落星矿脉。进入矿区需要任务凭证。",
      "content": "## 宗门概况\n青云宗依落星山脉而建，矿脉是其主要收入来源。\n\n## 出入制度\n弟子进入矿区，需要持有外务堂发放的任务凭证。",
      "children": [
        { "ref_id": "world_luoxing_mine" }
      ]
    }
  ]
}
```

### index.json：程序派生的查找入口示例

`file` 相对于本例的 `world/` 目录。`ancestor_ids` 从最上层祖先排列到直接父节点；它由完整节点的嵌套与引用关系计算，不由 Agent 手工维护。`root_ids` 是整棵逻辑树的根，不是所有文件顶层节点的集合。

```json
{
  "schema_version": 1,
  "root_ids": ["world_qingyun"],
  "by_id": {
    "world_qingyun": {
      "title": "青云宗",
      "summary": "东境修行宗门，控制落星矿脉。进入矿区需要任务凭证。",
      "kind": "faction",
      "ancestor_ids": [],
      "file": "qingyun.json"
    },
    "world_luoxing_mine": {
      "title": "落星矿洞",
      "summary": "青云宗西侧的废弃矿洞，分三层。下层有侵蚀神识的黑雾。",
      "kind": "location",
      "ancestor_ids": ["world_qingyun"],
      "file": "luoxing.json"
    },
    "world_black_mist": {
      "title": "矿洞黑雾",
      "summary": "只存在于矿洞下层，会侵蚀神识。火把和屏息均无法抵御。",
      "kind": "rule",
      "ancestor_ids": ["world_qingyun", "world_luoxing_mine"],
      "file": "luoxing.json"
    }
  }
}
```

重建时先扫描世界志内容文件，收集每个完整节点的 ID 与文件位置，再解析嵌套及 `ref_id` 关系，校验引用、单一父节点和无环约束，最后生成索引。世界志正式内容必须能独立于索引被枚举；索引不能成为发现内容文件的唯一入口。

## 读取案例

作者要写林凡进入矿洞，Context Agent 先搜索矿洞名称或相关描述，拿到摘要和相关节点信息，再批量读取矿洞本身、黑雾规则及青云宗制度。只查询黑雾时，可以定位 `luoxing.json` 并仅返回 `world_black_mist` 的内容；需要整个副本时才展开子树。缺少细节时继续检索正文，不把摘要或一次搜索未命中视为事实不存在。

读取结果应带节点 ID 与来源位置，供 Context Pack 保留依据；版本标记与历史章节适用范围的具体协议尚未细化。分层读取是可用能力，不是每次问答必须执行的固定步骤。
