# Writing Brief：第一版设计草案

本文将已经确认的 Writing Brief 职责具体化为字段和示例，供本轮讨论；具体字段尚待用户确认。它由 Context Agent 根据作者已经接受的方向整理，表达本次写作要求，与提供作品依据的 Context Pack 共同组成 Writing Package。

## 后续讨论确认的写作闭环

用户指出，任务交接字段齐全仍可能产生流水账，不能用 Brief schema 本身承诺写作质量。已确认增加章级概述和章内事件时间线构成的 Chapter Plan，并采用“先看方案、再写正文、写后可返修”的过程；下方 Brief 字段仍是待调整草案，不因流程获认可而自动定稿。

Brief 表达作者想要什么；Writer 根据 Brief 与 Context Pack 提出具体如何展开的 Chapter Plan。方案除事件顺序外，还需说明事情为什么衔接、人物为什么作出选择、这些选择带来什么变化，不强制固定场景数或每章都有强冲突。方案发现明显问题时先修改方案，再展开正文。

Context Agent 对照作者意图与作品依据检查方案，正文完成后再检查预期效果是否有实际描写支撑，并给出定位明确、能执行的反馈。正常检查修改由两个 Agent 内部完成，不要求作者逐步确认；改变作者目标或缺少关键创作授权时再回到对话。普通措辞修正仍可由 Context Agent 直接完成。

章节方案是可修改的任务产物，不冻结，也不写入正式剧情事实。它不同于全书大纲和定稿后的章节摘要；与旧 PRD“本章安排”的具体数据承接关系尚待明确。Chapter Plan 的具体 schema 与质量评估用例待定义；正文检查反馈已有[第一版 schema 草案](chapter-review.md)，修改暂不设固定轮次上限。必须通过实际章节对比检验改善，而非靠增加流程步骤或模型自评分宣称可靠。

## 质量门禁：本轮明确的检查范围

用户提出先检查四类有作品依据或任务要求可供对照的问题：

| 检查项 | 对照依据 | 示例 |
|---|---|---|
| 内容是否符合本次要求 | 已接受的 Writing Brief | 要求本章只产生怀疑，正文却确认了秘密身份。 |
| 人物动机是否符合人设 | 人物画像、关系、认知与相关剧情 | 人物的选择是否有符合其经历、处境与所知信息的理由。 |
| 登场人物的道具、法术是否正确 | 人物持有物、掌握能力、当前状态及本章内的变化 | 已交给他人的法宝又被无交代地取出使用。 |
| 道具、法术的使用效果是否正确 | 资料库中的效果、条件和限制，以及具体物品状态 | 明确只能抵挡物理攻击的法宝，被直接用于免疫精神攻击。 |

这四项是本轮讨论确定的检查范围，不代表所有判断都能由程序确定，也不代表通过后文章必然精彩。人物动机的合理性、抽象的预期阅读效果尤其涉及语境判断。

已确认的判断边界：

- 明确违反已接受要求或既定事实的问题必须修正，不能当作可忽略的审美建议。
- 人物行为反常不直接等于人设冲突，应结合正文和前文判断是否有充分理由，不能仅凭性格标签打回。例如胆小的人为救唯一的亲人冒险，可以是有支撑的选择。
- 资料未记录或 Context Pack 未收录，不等于事实不存在。先补查，不因“没查到人物会某法术”直接认定“人物不会该法术”；补查仍不足时也不能伪装成已证实的冲突。

## 编辑建议：改善表达，不作为独立硬门禁

已确认把“没有违反事实或要求，但表达仍可改善”的问题作为编辑建议。例如打斗连续重复“出招—挡住—再出招”，人物处境没有变化，可以指出对应段落与修改方向，而不能只给出“不够精彩”的评价。

编辑建议必须定位具体段落，说明具体问题与修改方向。可以据此修改，但不能因模型持续认为“不够好”而无限重写；编辑判断不单独阻止章节交给作者，也不引入模型评分作为交付门槛。作者明确要求的效果没有实现，仍按质量门禁中的要求符合性处理，不降为可忽略的审美建议。

用户明确暂不设置内部内容修改与复查的固定轮次上限；此前“初稿后最多两轮”的建议未采纳。不设固定轮次不改变编辑建议不单独阻止交付的边界，也不等于要求持续润色。内容修改与网络失败、中断后的技术重试是不同事项。

## 检查反馈：已确认的最小内容

每条交给 Writer 的反馈至少说明三件事：

1. 哪里有问题：定位具体正文片段。
2. 为什么有问题：说明违反的已接受要求或作品设定及依据；如果只是编辑建议，明确区分，不能伪装成事实冲突。
3. 希望改成什么效果：给出修正目标，不要求检查者替 Writer 写好替换正文。

例如：正文写“护心玉挡住了精神攻击”；资料库明确其只能抵挡物理攻击；修正目标为修改应对方式，不能扩大护心玉的能力。此例仅说明反馈粒度，不新增正式作品事实。

上述内容已确认；具体字段名、定位方式、来源引用格式见[章节检查结果 schema 草案](chapter-review.md)，字段设计仍待本轮对账，不新增评分表。

## 修改后的复查范围

已确认：正文修改后，对当前整章重新检查上述四项质量门禁，既核对上一轮指出的问题是否修复，也检查修改是否引入新的要求或设定冲突，不只逐项关闭旧问题。

例如，Writer 把“护心玉抵挡精神攻击”改为“施展清心诀”，还需检查该人物是否掌握清心诀、施展条件与效果是否符合设定，不能仅因不再误用护心玉便判定通过。此例仅说明复查范围。

复查不要求每轮重新提出一遍文笔改善意见，编辑建议仍不单独阻止交付。暂不设置固定修改轮次上限。

待讨论：补查后仍无法确定时如何处理，以及不依赖固定轮次的终止条件。反馈的具体 schema 已形成草案，尚未视为确认。本轮仅记录设计决定，不执行试写或实现自动修改流程。

## 什么时候生成与更新

作者与 Context Agent 确定方向、准备调用 Writing Agent 时生成。不要求先填表，也不要求每轮问答都生成 Brief；用户明确要求直接写且意图足够清楚时，可直接整理，不另设强制确认页面。

Context Agent 只保留接受的要求，舍弃讨论中的废案。作者允许 Agent 自行安排的范围也可以记录，但不能把 Agent 未获接受的剧情建议冒充作者意图。未知的非必要细节保持留白；足以改变本章人物、事件或结果且又未获创作授权的问题，先在正常对话中澄清，不假装 Brief 已完整。

局部修正不必重新生成 Brief；当作者改变人物、事件、动机、因果、结果或揭示时机时，更新 Brief 并为新的 Writing Agent 准备输入。`rewrite_chapter` 的原正文与相关事实在 Context Pack 中提供；Brief 说明这次要保留或改变什么，不复制整篇旧稿。

## 字段及边界

| 字段 | 类型 | 回答的问题 |
|---|---|---|
| `schema_version` | integer | 这份输入遵循哪个格式版本？ |
| `id` | string | 这份 Brief 的稳定标识是什么？ |
| `chapter_id` | string | 本次写哪一章？ |
| `mode` | enum | 新写 `write_chapter`，还是结构性重写 `rewrite_chapter`？ |
| `intent` | string | 本章想推进什么、达到什么效果？ |
| `requirements` | string[] | 已经接受、需要做到的具体要求有哪些？ |
| `constraints` | string[] | 本次写作应遵守哪些明确边界？ |
| `ending` | string 或 null | 本章结束时希望停在哪里、形成什么局面？尚未指定则为 null。 |
| `creative_scope` | string[] | 哪些地方明确允许 Writer 自行安排？ |
| `leave_open` | string[] | 哪些事情有意保持未定，本次不要替作者补成设定？ |

`intent` 可包含剧情推进和读者感受，不强制填写主题或固定叙事模板。`requirements` 可记录高层事件、需要的场景、叙述视角、篇幅等本次已接受要求，不强制每章都有起点、转折、高潮、结尾的完整分镜；顺序要求只有明确写进要求时才成立。

`constraints` 只记录本次会影响落笔的边界，例如“不能在这一章确认卧底身份”。已有的法宝规则、人物经历、伏线依据等仍以 Context Pack 中的资料承载，不在 Brief 维护第二份事实档案。本次偏好不会自动改为全书笔法；若作者要求改动既有正式设定，需先明确改设定的意图及影响，不把事实冲突隐藏成普通写作要求。

`creative_scope` 与 `leave_open` 不同：前者允许创造，后者保留未知。Writer 通常可以完成措辞、段落和不引入长期设定的局部表现，不需要逐句申请许可；`creative_scope` 用来明确超出这些基本表达选择的授权范围，也可以重申重要边界。列表为空表示没有额外记录，不表示拥有无限创作权限，也不表示不能写。

`ending: null` 表示作者未指定结尾，不等于章节不能结束；Writer 可在已有目标和授权范围内组织收尾，但不能因此加入未授权的重大转折。所有文本字段允许 Markdown。

## WritingBrief schema

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "WritingBrief",
  "type": "object",
  "additionalProperties": false,
  "required": ["schema_version", "id", "chapter_id", "mode", "intent", "requirements", "constraints", "ending", "creative_scope", "leave_open"],
  "properties": {
    "schema_version": { "type": "integer", "const": 1, "description": "格式版本" },
    "id": { "$ref": "#/$defs/text", "description": "本份 Brief 的稳定标识" },
    "chapter_id": { "$ref": "#/$defs/text", "description": "目标章节的稳定 ID" },
    "mode": { "type": "string", "enum": ["write_chapter", "rewrite_chapter"], "description": "新写章节或结构性重写" },
    "intent": { "$ref": "#/$defs/text", "description": "本章目标与希望达到的效果，允许 Markdown" },
    "requirements": { "$ref": "#/$defs/text_list", "description": "已经接受的具体写作要求，未限定时可为空列表" },
    "constraints": { "$ref": "#/$defs/text_list", "description": "本次明确边界，不复制完整事实档案" },
    "ending": { "type": ["string", "null"], "minLength": 1, "description": "指定的结束位置或局面；未指定为 null" },
    "creative_scope": { "$ref": "#/$defs/text_list", "description": "明确允许 Writer 自行安排的范围" },
    "leave_open": { "$ref": "#/$defs/text_list", "description": "本次需保持未定、不擅自补全的事项" }
  },
  "$defs": {
    "text": { "type": "string", "minLength": 1 },
    "text_list": { "type": "array", "items": { "$ref": "#/$defs/text" } }
  }
}
```

Schema 验证字段和值类型，不证明作者已经接受要求，也不判断要求是否互相矛盾。目标章节归属、新写时的 ID 分配、重写时的原稿定位，以及 Brief 与资料版本的一致性在后续任务协议中定义。本设计不引入冻结上下文或必须由作者检查 Brief 的额外步骤。

## 完整示例：准备第 91 章

以下为虚构案例，假定作者已经接受下列方向及授权范围。它示范写作要求的表达，不新增实际章节或正式剧情。沈砚的真实身份、封蜡原文、相关人物状态和写法范例将放在 Context Pack 中。

```json
{
  "schema_version": 1,
  "id": "brief_chapter_0091",
  "chapter_id": "chapter_0091",
  "mode": "write_chapter",
  "intent": "让林凡围绕封蜡试探沈砚，保留怀疑，同时通过沈砚的实际帮助让两人的关系有所推进。",
  "requirements": [
    "林凡主动提起封蜡，观察沈砚的反应。",
    "沈砚给出能解释部分疑点的回答，但仍有所隐瞒。",
    "安排一个不涉及新能力或重大设定的小事件，让沈砚实际帮助林凡；不能只用旁白宣布关系变好。"
  ],
  "constraints": [
    "本章不确认沈砚的卧底身份，林凡仍处于怀疑阶段。",
    "不能靠林凡突然放弃判断来维持秘密。",
    "不把沈砚写成纯粹利用林凡、毫无真实感情的人。"
  ],
  "ending": "林凡没有消除疑虑，但愿意暂时与沈砚继续同行；信任比章初增加一点，尚未达到无条件托付。",
  "creative_scope": [
    "可以安排这次试探的具体对话、动作和情绪节奏。",
    "可以设计上述小事件的具体经过，但不新增重要角色、能力或世界规则。"
  ],
  "leave_open": [
    "沈砚最终会选择宗门任务还是林凡，本章不替作者确定。"
  ]
}
```

例如这份 Brief 要求“本章不确认身份”，Context Pack 则应提供为什么林凡目前只是怀疑、沈砚在隐藏什么、先前封蜡事件到底怎么写。两者共同支撑写作，Brief 本身不声称包含全部依据。
