# 本地任务界面 · 按用户旅程走查

核对日期：2026-10-04。用户已认可六段旅程，本次据此检查当前工作区源码、角色提示词和流程 Skill，并调整交互原型。此次没有调用真实模型、读取用户小说内容或重新进行 v0 实机验收；原型使用明确标注的固定样稿。

## 六段旅程与现有能力

| 旅程 | 当前业务依据 | 页面适配缺口 | 原型中的处理 |
|---|---|---|---|
| 进入、新建作品 | `main.ts` 按标识或路径打开作品；`layout.ts` 创建独立作品、任务及产物目录 | 没有浏览器作品列表、显示名或上次访问作品记录；无任务时 `latestTask` 会抛错，需要入口回退到创建首个任务 | 顶部作品切换；新建直接进入空白对话；分别恢复每部作品最近任务 |
| 讨论、查资料、准备写作 | Context 提示词允许空白开场；`answer` 只查询回答；`write_canon` 校验作者真实确认；`save_package` 保存本章要求和材料 | 消息与确认需要在网页里呈现和回传；不能把每次输入都变成写稿请求 | 讨论、资料确认和写作意图分开演示；确认卡复述具体变更，点击后记录明确的作者确认 |
| 方案、写作、检查 | `write-chapter` 由 Context 检查方案，Writer 写正文，Reviewer 返回结构化结果；Hub 保存关联产物与执行通知 | 没有页面执行摘要；角色运行状态不能直接当作整件任务的完成状态 | 自动展示准备、方案、正文和检查过程；详情中标角色；交稿给正文入口及检查摘要 |
| 阅读与修改 | `send_message` 只发给 Writer；纯措辞通过 `save_revision` 存新版本；Reviewer 按初稿身份检查 | 需要全文阅读、对所读版本提出意见，以及明确版本归属 | 消息里的每份稿件可打开；修改带所读稿件引用；旧稿保留，修改后的稿件另行交付 |
| 定稿与同步 | `finalize(draftId)` 先保存正式章节、登记待同步，再通知 Context；Context 提出和应用变更，Sync Checker 核对；`apply_sync` 校验引用与作者确认 | 需要指定当前阅读版本、分别表达正文与同步状态、显示冲突和恢复入口 | 定稿确认注明作品、章节、版本；正文已保存后独立显示同步进展；中断或冲突不抹掉定稿状态 |
| 切换、停止和恢复 | 不同作品数据目录独立；`openWritingSession` 恢复选中作品最新任务；进程退出后旧子 Agent 标为 terminated | CLI 阻止直接切换会话；没有全局单任务执行约束、浏览器重连或跨作品查看；`stopAll` 只停运行中子 Agent，未覆盖主 Agent | 切换可查看另一作品；其他作品运行时禁止发起新请求，显示返回及明确停止入口；刷新恢复演示记录，进程退出场景显示中断 |

源码路径均位于 `v0/src/`；角色与流程分别位于 `v0/prompts/sp/` 和 `v0/prompts/skills/`。

## 必须保留的边界

- 方案审核、疑点补查、有限返修等，是现有 Agent 提示词与 Skill 规定的行为；页面应呈现实际事件，不根据等待时长猜测真实进度。原型中的定时演示不代表生产进度来源。
- 作者确认仅对复述的具体变更有效。确认资料、改变写作方向和定稿分别针对明确对象，不共用一个笼统的“同意”。
- 交稿不等于检查全部通过；如达到返修停止条件，须披露剩余问题。资料同步失败也不等于正文定稿失败。
- 作品显示名、最近访问记录、作品扫描、消息传输、只读预览、整体停止和运行管理，都属于待实现的页面适配；本次只优化设计原型。
- 单个活动作者任务是已确定的 MVP 范围，不是现有 CLI 具备跨进程全局锁的证据。

## 本次设计取舍

保留当前作品、作品切换和新建、最近任务对话、执行摘要、正文阅读、修改、定稿及必要的继续处理。移除独立任务管理侧栏、内容目录、盲比、审计、模型设置，以及作者逐章审批方案的操作。已有业务能力不要求全部在首版设独立入口。

## 原型验证范围

验证空白与多作品入口、讨论不会自动写稿、资料确认、自动方案到交稿、返修、新旧稿明确归属、指定版本定稿、同步完成/冲突/失败、执行中跨作品查看与停止、页面刷新恢复和移动宽度阅读。完整浏览器验证结果记录在 `design-validation.md`。
