# 项目布局与组件模式

本包设计姿态为 `incremental`。基线是 2026-10-05 当前 `v0/ui/` 的本地写作任务页，包含同作品的任务切换与只读正文阅读。此文档区分已存在的界面和本包建议的完整过程流，供原型实施对照。

## 证据与提取范围

- 视觉参考：`refs/current-task.png`（1440 × 1000，正在执行的真实任务页）和 `refs/current-noya.png`（1440 × 1000，作品选择弹窗）。后者有遮罩和模糊，不代表任务页的常态背景、密度或主体结构。
- 首要代码：`v0/ui/tokens.css`、`v0/ui/app.css`、`v0/ui/index.html`、`v0/ui/app.ts`，均完整读取；交互实现也用于确认打开、返回、折叠、只读和任务归属。
- 配置扫描：当前运行界面没有独立 design/theme 文档、Tailwind 配置、Figma 链接或组件库。`v0/package.json` 表明界面是原生 HTML/CSS/TypeScript，未依赖通用 UI 库。
- 当前 UI 集中在上述 4 个文件，不能虚构 8–10 个组件文件。实际取样覆盖 12 类组件：品牌及作品切换、连接反馈、任务标题及切换、作者消息、Agent 消息、正文卡片、执行摘要和 Agent 行、输入区、只读阅读器、作品选择弹窗、任务选择弹窗、错误及提示反馈。
- 历史 `docs/prd/*/canvas/` 是设计产物，不是本轮产品骨架的依据；不沿用旧作品管理导航。
- `tokens.css` 的生产变量完整原样保留。参考 `pulse-dashboard/tokens.css` 的变量类别补齐中性色别名、字体别名和各级行高；补充少量当前组件使用值，不更换任何生产色值。组件布局应写在 `shell.css` 或页面样式中。

## 视觉总貌与高频值

- 低对比的暖灰纸色背景 `#f1eee8`、近白纸色表面 `#fbfaf7`，正文墨色 `#211f1c`。画面依靠留白、文字层级和细线分区；内容密度适合长时间阅读。
- 朱砂 `#a33f32` 用于品牌、发送、主要确认动作和少量选择强调，截图中面积很小。墨绿 `#2f6558` 用于在线状态、Agent 标记和执行点。禁止把整块进度区涂成鲜艳主色。
- 界面字体为系统无衬线，正文阅读为宋体/衬线，品牌为 Georgia。图标小且简单；Agent 标识是带细线边框的斜体 N，不是大型头像或卡通人物。
- 组件 CSS 中高频色引用：secondary text 23 处、border 18 处、primary 17 处、surface 17 处、tertiary text 12 处、text 11 处、accent 9 处。主色引用数量不等于视觉面积，应以截图的小面积强调为准。
- 高频字号为 10–13px 的辅助文字和控件；对话正文 14px，任务标题 19px，正文阅读 17px。已有 token 的 md 是 13px，不应误用为对话正文的唯一尺寸。
- 高频圆角为 8px；按钮 7px，正文卡片 11px，输入框 13px，弹窗 15px。常态任务区不额外套大白卡片，阴影通常为无或 xs，浮层才用 lg。

## 全局布局

- 导航类型：单顶部品牌栏，内部为 Noya 品牌、竖线、作品切换、右侧本机连接状态。没有固定侧栏或管理菜单。
- 顶栏：桌面高 78px、左右 padding 36px，底部 1px 暖灰细线。作品名可截断；连接状态用 6px 绿点和 11px 辅助文案。
- 工作区：顶栏以下占满剩余高度；任务页采用 flex 纵向布局，中央最大宽度 1080px，左右自动留白。1440px 截图中实际文本/输入宽约 984px，左缘 x≈228、右缘 x≈1212。
- 大屏 ≥1500px：任务最大宽度 1050px，内部左右 padding 70px。一般桌面内部左右 padding 48px。
- 页面滚动：对话 feed 独立滚动，标题和底部输入保留位置；不把整个视口做成文档滚动。reader 打开后有独立阅读滚动区。
- 正文打开时：桌面右侧 reader 占约 51%、最大 850px、最小 360px，左侧任务区剩余宽度，左右内边距缩为 30px；没有第三列。

## 页面骨架（已存在）

1. 顶部任务标题区：小字“写作空间”与任务数量胶囊同一行，下面是当前任务标题、当前状态；右侧轻描边“＋ 新建任务”。任务标题单行截断，完整文字保留 title。
2. 中部对话区：作者内容靠右放入浅纸色气泡，Agent 回复直接平铺在背景上；消息间距 30px。每条 Agent 回复上方是小 N 和 `CONTEXT AGENT` 标签。
3. 已保存正文：以可点击正文卡片出现在对话中，展示版本、状态标签、衬线标题、字数/检查摘要与“阅读全文 ↗”。打开的是只读阅读器。
4. 执行摘要：置于对话/流式回复之后，以顶部细线、6px 墨绿执行点、一句当前动作和靠右“展开记录”组成。它属于正在查看的任务，不是全局统计栏。
5. 必要的决定、失败或同步提示：位于 feed 内，边框与 10px 圆角，信息或控制来自原主任务。
6. 输入区：固定在任务列底部，带轻微背景渐变衔接。13px 圆角纸色输入容器，左下辅助文案，右下“停止”/“继续任务”等文字动作和 34px 朱砂发送按钮。下方是极小的快捷键与保存提示。

## 组件风格

### 按钮与输入

- 主按钮：朱砂实底、白字、7px 圆角、12px 字号、10px × 17px padding；hover 使用 darker primary。仅任务的主要动作使用。
- 次按钮：纸色背景、1px strong border、同样的尺寸与圆角。轻按钮为透明底和 secondary text，hover 才变朱砂。
- 发送：34px 方形、8px 圆角、向上箭头。关闭：32px 方形、6px 圆角、透明底的 ×。
- disabled 原实现将不透明度降至 .42（发送 .3）；禁用必须可见且有上下文原因，不仅靠颜色。
- 输入是整个 composer 的边框，不给 textarea 再加框。textarea 14px/1.8、最小 54px、最大 180px；placeholder 使用 tertiary。focus 用温和的朱砂边线和极浅光圈。
- 键盘 focus-visible：2px 朱砂 outline、4px offset；summary、按钮、可聚焦区域均保留可见焦点。

### 内容卡片与状态

- 正文卡片：1px border、11px 圆角、20px × 23px padding、xs 阴影；hover 加朱砂边线和 sm 阴影。标题 21px 衬线，元数据 10–11px。
- badge：10px、2px × 7px padding、4px 圆角。墨绿浅底表达已保存/可靠事实；暖黄浅底用于待检查或需要留意的信息。
- 新增记录不需要表格、斑马纹、数值概览卡或卡片网格。优先沿用纵向列表与细线，工具参数和原输出保持可读。
- 空任务是居中纸页图形、衬线大标题和简短邀请文案；“没有子任务”仅需在执行区内解释，不重复渲染整页空状态。

### 执行摘要与 Agent 行

- 已有 `.execution`：与上文间隔 22px、12px secondary text；`details` 顶部 1px border、上内边距 13px。
- 已有 `summary`：横向 flex、gap 8px，右侧 10px tertiary 展开/收起文本。进行中用 6px 墨绿呼吸点，1.8s 周期。
- 已有 `.agent-row`：左侧 1px 纵线、左 padding 15px、上下 padding 8px；行内 gap 10px，允许换行，detail 使用 tertiary。实际实现目前只展示角色、粗状态、detail。
- 已有汇总优先“正在停止全部执行”，其次当前运行角色，再主任务 activity；无运行时展示工作记录数量。它没有目标、更新时间、轮次、可打开动作历史等本包增量。
- 当前代码用“本轮完成”映射 Agent idle，是既有文案事实。本轮原型必须遵循需求将“本轮结束”“结果已保存”“作者定稿”分开，不能从旧文案继承完成语义。

### 只读阅读

- reader 顶部细线标题栏：左侧“正文阅读 / 只读”，右侧关闭；元数据在正文前，标明作品和具体版本。
- 正文 17px/2.2 衬线、字距 .4px，标题 28px/1.6；左右留白 `clamp(28px,4vw,70px)`，段间 1.25em。
- 检查结论在正文下方的细线折叠区；阅读结尾有低对比“— 本版结束 —”。
- 原正文页底部保留“对这版提意见”“将这版定稿”。子任务的“结果已保存”不可调用或替代定稿动作；检查/核对报告应使用只读结果页面和“返回执行记录”，不为其伪造正文定稿按钮。
- 返回后恢复原 Agent 筛选、展开状态与滚动位置。新结果不可自动替换作者正在读的旧版。

### 作品与任务切换弹窗

- 作品切换：桌面宽 min(440px, viewport−32px)，最大高 80dvh，15px 圆角、lg 阴影、25px 内边距。遮罩为半透明墨色并模糊 3px；只有弹窗打开时显示。
- 作品选项：一列列表，7px gap、14px padding、8px 圆角；选中或 hover 使用极浅朱砂底和细边线，右端小字显示当前/执行中/箭头。
- 任务切换：桌面宽 min(560px, viewport−32px)，28px padding。上方作品眉题、24px“写作任务”和数量；其下新建入口，再下独立可滚动任务列表，列表最大 min(48dvh,420px)。
- 每个任务行：当前选择圆点、13px 标题、10px 时间/短编号、右侧低调状态。执行中墨绿、待决定朱砂；选中纸色背景和细边线。任务选择和实际运行状态是两件事。
- 切到其他任务但仍有任务运行时，顶栏下方用暖黄浅底提示条显示实际运行归属和“返回任务”，可复用现有入口维持方向感。

## 反馈、实时与窄屏

- 连接错误：顶栏下方横向浅红条；任务错误在该任务 feed 内浅红卡片。新增断线说明要写“暂时不能确认最新状态”，不可把连接中断绘成子任务失败。
- Toast：底部居中 25px，墨色底、纸白字、12px、8px 圆角、md 阴影，最多 90vw；现有实现持续 4 秒。详细执行失败用就地信息，不只依赖 Toast。
- 已有新消息保护：读者离开底部时出现“↓ 查看新内容”，不强迫拉回。新增执行记录沿用该原则，不重置已展开的行、Agent 筛选或输入。
- ≤780px：顶栏高 64px、18px 左右 padding；任务标题/对话左右 22px，输入左右 16px；消息间距 24px、正文 13px。reader 变为全屏，原任务暂时 inert，关闭后回到原位置。
- ≤600px：任务弹窗 padding 22px × 17px，标题及行内字段压缩；状态允许合理换行，不能挤出水平滚动。子任务详情也应由 inline 纵向展开或单一全屏阅读承载，不压出第三列。
- Reduced motion：已有样式关闭全部动画、transition 和平滑滚动。呼吸点关闭动画后仍保留点和文字状态。

## 本包完整过程流的使用方式

用户最新要求 Main 与 Sub 一样展示所有可见过程；以下是当前原型规范。上文标为已存在的执行摘要和角色行仅是生产界面事实，不再作为本包内容模板。

- 运行记录按 Agent 分别呈现：主信息流只显示作者消息与 Main 过程，每个 Sub 详情只显示该 Sub 自己的消息、思考、调用、输出、错误、状态与结果。各处使用相同的通用内容规则。
- 连续内容沿用所在视图的身份；作者消息使用自身消息样式，单个 Sub 的详情身份由浮层标题提供。轮次与时间保留在记录悬停信息、工具和系统展开详情中，不逐条铺设元数据行。Main 和 Sub 内部工具行相同，原名、参数与输出仍可读取；陌生工具或身份仍通用可读。
- 思考与工具明细默认折叠，正在运行也不自动打开。连续思考与普通工具按同 Agent、同执行成组，默认收起；摘要使用自然的轻量动作概括，箭头紧随文本。展开后的工具、思考按顺序平铺成低强调活动行，不套日志卡片；消息使用正常内容层级。原工具名、参数、输出、思考原文可继续展开。保留运行、错误、停止、中断与未知状态。
- 动作摘要只概括可确认的事件与参数：文件数不能从产物编号推断，搜索/命令次数不从陌生工具名称猜测；未知动作保留原工具名。思考时长只有明确时长或实际起止才显示，不从相邻事件时间差编造。
- 在每个 Agent 自己的流中，消息、执行事件、保存结果或派发结束当前组，其他 Agent 的活动不打断分组。组身份和用户主动展开状态不随追加内容改变。
- 主信息流保留 Main 的紧凑派发入口，使用父子节点分支图标和轻量青绿标识，与代码工具区分；只展示子任务名称、状态与查看入口，目标及结果数量移入详情；Sub 的运行记录及保存结果位于该 Sub 详情，原派发调用可展开。
- 输入框上方的子任务胶囊向上展开浮层，锚定输入区，不使用遮罩、背景模糊、模态框或焦点环绕；页面和输入仍可操作。再次点击胶囊、关闭、Escape 或点外部收起。
- 浮层两层：任务列表显示进行中优先与历史，选中后在同一浮层看 Sub 详情。详情头部有返回列表、任务名与关闭，派发及补充要求作为独立上下文，随后只呈所选 Sub 的运行记录及结果。
- 主信息流不因查看 Sub 详情切换或跳动；浮层独立滚动，内部沿用默认折叠和原文规则。浮层打开产物后返回同一详情和阅读位置。
- 窄屏浮层限制高度并滚动，避免超屏，输入始终明确发 Main。参考图只用于布局和展开行为，继续使用现有 Noya 纸色与字体。
- 工具采用轻量可展开行，展开后参数、执行中输出、最终输出和错误均可完整读取；长文本使用通用展开全文，不能用预览替代原内容。
- 实际可读的 thinking 照常显示；不可读内容说明事实，不补写。陌生内容类型保留可读原内容及归属。
- 持续更新合并到同一调用；并行调用各自保持归属，结束不重排已有顺序。已确认停止或中断时，无最终返回的调用明确标出这一事实并保留原输出。
- 保存产物用记录内入口打开只读阅读器，返回保留筛选、展开和阅读位置。保存、工具完成和作者定稿分别表达。
- 更新与新记录提示保护阅读位置、打开项和输入；Main 新记录提示仅对应 Main，Sub 更新只写入对应详情。切换任务后晚到内容只归原任务；停止和继续沿用原任务入口。
- 断线、执行中断、历史缺失与单项不可读分别说明已知事实，未知状态不推断失败。
- 此原型使用固定样例，统一过程流尚未标为当前产品已实现。
