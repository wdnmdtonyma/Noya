# 现有能力核对（2026-10-05）

此文件记录设计依据，不是产品需求正文。已核对当前工作区源码；历史记忆只用于定位，不作为当前实现结论。

## 已存在

- `v0/src/layout.ts`：每个写作任务独立登记 subagent；角色为 writer、reviewer、sync_checker。
- 实际状态为 running、idle、stopped、retired、terminated、failed；每轮记录开始/结束时间、结果列表、outcome 与 note。
- `v0/src/hub.ts`：Writing Agent 可在同一身份下继续新一轮；结构性重写退役旧 Writer；正文检查和同步核对创建独立 Agent。
- 结果类型包含章节方案、初稿、正文检查、资料变更核对。提交结果与结束轮次是不同事件。
- `v0/src/local-app.ts`：页面可获取子任务身份、角色、状态及失败原因/累计工作记录数；只订阅 Context 的当前动作与回复。
- `v0/ui/app.ts`：现有执行记录默认折叠，子任务行展示角色、状态和概括说明，没有具体目标、轮次和动作记录。
- 当前实现包含写作任务新建/切换，所选任务与实际执行任务分离，跨任务晚到响应不得覆盖所看任务。
- 页面只读阅读初稿；修改与定稿仍通过现有作者入口完成。
- 真实本机服务 `http://localhost:4317/` 本轮返回 200，供只读视觉参考。

## 统一过程展示的源码依据与当前缺口

用户本次明确要求 Main 与 Sub 使用同一套展示规则，保留所有可见过程。

- `v0/src/local-records.ts` 与 `v0/src/transcript.ts`：当前读取 Main 的作者/助手文字，提取仅限 text 内容；工具调用、工具返回与其他内容没有进入当前文字记录。
- `v0/src/local-app.ts`：当前实时订阅 Main 的助手文字与工具开始事件，工具开始被改写成业务动作提示；Sub 目前只提供身份与状态概括。
- `v0/src/local-contract.ts`：任务视图目前提供消息、初稿、Agent 摘要及当前活动，没有统一完整过程视图。
- 当前安装的 Pi 类型包含文字、可读 thinking、工具调用名称和 arguments、toolResult，以及 tool_execution_start/update/end；工具事件可携带父调用关系。thinking 的 redacted 内容为不可读数据，不能当作可读思考展示。
- `v0/src/hub.ts`：Main 与各 Sub 已有各自会话；业务角色、轮次、结果仍用于归属，不应该决定执行内容的呈现模板。

本轮产品表现需要统一显示消息、可读思考说明、工具调用与完整参数、中间输出、最终返回、错误和执行事件。多个 Agent 与并行调用保持归属和发生顺序，同一调用的持续更新保留已有内容。长内容折叠但可读全，未知身份或工具依同一规则呈现。

## 原型证据边界

原型使用固定样例，只验证交互故事；research-1 与 custom_probe 是验证陌生身份和工具能通用呈现的假设样例，不代表当前业务已提供这些能力。其他角色与状态基于现有类型。不连接模型、不读写作者真实作品，不作为产品实现或真实执行验收。

## 本轮展示规则迭代

用户最新反馈要求默认折叠思考、工具与技术原内容，连续思考和普通工具按同一 Agent、同次执行合并。消息、执行分界、产物与派发保持独立，折叠摘要仍提示失败。

Sub 的身份、真实派发任务、状态和保存结果可以用于专门定位展示：信息流保留独立派发卡，任务页另有固定子任务入口。两处定位同一过程，内部内容仍通用展示原文。此项是本轮 PRD 与固定原型表现，未标为当前产品已实现。

## 输入区浮层迭代

用户后续通过页面注释删除顶部 Agent／记录数及通用筛选，要求子任务入口位于输入框上方，展开为非模态浮层。两张参考图只用于入口、列表与详情的布局：Sub 详情在同一浮层保留 Main 实际派发要求和该 Sub 的通用过程，主信息流不切换。输入仍发给 Main，原执行控制保持，关闭浮层不停止工作。本轮是需求与固定原型更新。

## 活动摘要与平铺记录迭代

用户追加的 Codex 图片用于轻量动作摘要及展开后工具、思考活动行的表现。摘要可对明确工具活动作通用概括，Main 与 Sub 使用同一规则；不从业务角色推断内容，不把产物编号当文件，也不从相邻事件时间差编造思考时长。原工具名、参数、中间输出、最终返回与错误仍可读取。此项继续属于需求与固定原型表现。

## 各 Agent 独立记录迭代

用户最新明确不同 Agent 的运行记录分别展示。主信息流只呈现 Main，各 Sub 在其详情中呈现自己的过程与结果；派发及补充要求作为独立上下文保留。按各自流的顺序合并连续活动，Main 新记录提示仅对应 Main，其他 Agent 的更新保留在各自详情。本轮继续是 PRD 与固定原型，未改变真实产品代码或原始事件存储。

## 成果优先信息流迭代（2026-10-06）

子任务卡片上的成果来自对应 Sub 该次执行保存的结果（按 Sub 身份与执行次数关联），属于 Main 派发调用的返回展示，不把 Sub 的过程混入主信息流。当前产品是否能按次关联 Sub 的保存结果、提供"当前动作"实时事件，需在实现阶段核对；本轮仍只交付 PRD 与固定样例原型。
