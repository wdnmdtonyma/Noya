# 查看 subagent 任务进度

## 1. 背景与目标

作者把写作要求交给 Noya 后，常需要等待写手生成正文、检查员核对稿件。现在页面能告诉作者哪个角色正在处理，却看不到具体工作、最近做了什么，也难以分辨是仍在执行、没有提交结果，还是已经中断。

这次在原任务页提供可展开的子任务进度。作者能知道每个 subagent 在处理什么、执行到哪个已知动作，以及已经保存了哪些结果；离开再回来也能继续查看准确记录。

## 2. 产品逻辑

作者仍在原写作任务里提出要求。Context Agent 实际安排子任务后，执行摘要显示正在工作的角色和当前动作。作者展开列表，选择一个子任务，查看其目标、轮次、执行记录与结果；打开结果后，可以回到刚才的记录继续阅读。

执行状态和结果分别表达：一轮结束不代表已提交结果，保存初稿不代表作者定稿，检查通过不代表稿件已被接受。查看进度不会启动工作；修改、停止、继续和定稿仍通过原任务的入口完成。

[体验可点击原型](http://localhost:60084/p/01-tasks)。原型使用固定样例演示交互，预览服务存活期间可访问；同时附有可离线打开的原型。

## 3. 功能清单

| 功能 | 作者要回答的问题 | 入口 |
| --- | --- | --- |
| 看当前进度 | 谁在处理什么，最近做了什么？ | 原任务页的执行摘要 |
| 看执行记录与结果 | 这一轮发生了什么，留下了什么？ | 展开的子任务详情 |
| 离开与恢复 | 切换、断线或中断后，哪条记录仍然可信？ | 原任务切换、返回和继续入口 |

## 4. 功能描述

### 4.1 等待时查看当前进度

作者提出要求后，继续在对话中阅读 Context 的回复。子任务真实开始，页面才显示相应进度。

- **从主任务进入**
  - 执行摘要显示正在工作的角色与当前已知动作，点击可展开子任务列表。
  - 尚未安排子任务时，说明“尚未安排子任务”；Context 准备材料的动作仍由主任务提示承接。
  - 正在执行的子任务优先展示，其他记录按最近工作时间从新到旧排列。相同角色的多次任务各自保留。
- **识别具体工作**
  - 每项显示角色、可区分的短标识、工作目标，以及可确认的章节或版本。
  - 展开后显示当前轮次、状态、最近动作与动作发生时间。一轮指该 Agent 从开始处理一次要求到结束本次处理。
  - 目标或归属资料缺失时明示无法确认，不使用另一个任务或版本补齐。
- **观察真实变化**
  - 动作有记录才更新；区分正在查阅、写作、提交与已确认结束，不把动作开始当成完成。
  - 没有新动作时，保留最后已知动作及更新时间。主任务整体仍在执行，不代表每个子任务都在运行。
  - 无法确认细分动作时显示“正在处理”；没有事实依据的百分比、字数进度和预计完成时间不作为进度。

| 子任务情况 | 展示 | 结果怎么处理 |
| --- | --- | --- |
| 正在处理一轮要求 | 运行中，显示当前轮次与最近动作 | 已提交结果可查看，不代表本轮已结束 |
| 正常结束一轮 | 本轮结束，明确有结果或未提交结果 | 已有结果保留；作者可在原对话继续 |
| 已停止 | 已停止，保留最后动作与结束时间 | 已保存结果仍可查看 |
| 已被新 Agent 替换 | 已结束使用，说明后续由新 Agent 处理 | 原轮次和结果留在旧 Agent 下 |
| 未完成的执行因程序退出而结束 | 执行已中断 | 未结束轮次标中断，历史已完成轮次保留原结论 |
| 执行失败 | 失败，说明可理解的原因；原因未知就直说 | 部分结果可读，失败提示同时保留 |

尚未开始第一轮的记录显示尚未开始，不借用“本轮结束”。Agent 在重启后已不可继续使用，也不改写其历史轮次已经结束或已有结果的事实。

### 4.2 展开记录，读取已保存结果

作者想确认一项工作具体做了什么时，展开对应子任务。详情按轮次组织，不把不同轮的动作和结果混在一起。

- **读执行记录**
  - 每轮显示开始时间、已知动作及时间、结果提交和结束结论。业务动作使用作者能理解的语言。
  - 新一轮有独立编号和时间；上一轮的结果不会成为新一轮的“最近提交”。
  - 同一 Writing Agent 的修改接在新轮次下；结构性重写产生新的 Writing Agent，旧 Agent 的记录仍可读。
- **处理持续更新**
  - 更新不收起展开项，不重置对话、记录或结果的阅读位置，也不覆盖未发送输入。
  - 作者正在读旧记录时，提示有新记录；点击后才跳到最新位置。
  - [假设] 每轮先显示最近 20 条记录，向前逐段查看更多；旧轮次按需展开，避免长历史一次铺满任务页。
- **读取结果与返回**
  - 只有实际保存的结果提供读取入口；显示名称、版本或处理对象、所属轮次及必要的结论。
  - 结果以只读方式打开，关闭或返回后回到原子任务和阅读位置。窄屏保持同样的返回路径。
  - 部分结果已经保存后又失败或停止时，两种事实同时保留；不能用结果卡片掩盖失败，也不能因失败隐藏结果。

| 结果 | 显示与读取 | 不能混淆的结论 |
| --- | --- | --- |
| 章节方案 | 对应章节、方案内容与提交时间 | 已提交方案不代表已通过 Context 的检查 |
| 初稿 | 章节、明确正文版本、只读全文；沿用现有提意见和定稿入口 | 已保存正文仍是初稿，检查结果另行显示 |
| 正文检查 | 被检查的具体版本、结论与发现的依据 | 新版本产生后，旧检查仍只属于旧版本 |
| 资料变更核对 | 定稿章节、对应变更清单与核对结论 | 核对通过不代表变更已写入正式资料 |

正常结束却没有保存结果时，详情显示“本轮结束，未提交结果”，并引导作者回原对话询问或继续。执行记录展示可公开的工作动作与结果，不展示隐藏思考或原始提示词；技术错误转成可理解的原因。

### 4.3 切换任务后回来

作者可以在等待任务 A 时查看任务 B，或切换到另一部作品。进度始终跟随实际所属任务，查看行为不会派发、重试或停止 subagent。

- **切换与返回**
  - 当前任务只展示自己的子任务。实际执行任务仍通过现有提示提供返回入口。
  - A 的晚到动作和结果只更新 A；不插入 B，也不覆盖 B 的展开项和输入。
  - 返回 A 时显示它的最新事实，同时恢复此前展开项。刷新同样恢复当前任务，不重发上一条要求。
- **继续原工作**
  - 停止、失败或中断后，作者使用原任务的继续入口或对话；详情不新增独立执行控制。
  - 正在停止时显示“正在停止”，实际结束后才显示已停止；既有子任务结果仍可查看。
  - 旧 Agent 已不可继续时，Context 根据保存材料重新安排；新 Agent 独立记录，历史不改名或合并。
- **长时间没有新记录**
  - 保留最近更新时间，便于作者判断等待情况，不因静默自动失败或重试。
  - 作者仍可在原任务询问或停止；不会因为打开详情又启动一次相同要求。

### 4.4 状态暂时无法确认时

作者可能只是页面断线，也可能程序确实退出。页面先说明能确认的事实，再给出恢复路径。

| 情况 | 页面表现 | 恢复路径 |
| --- | --- | --- |
| 页面断线 | 保留最后进度与结果，注明最新状态尚未确认；不显示仍在实时更新 | 自动重连；可读已加载内容，未加载结果说明暂不能读取 |
| 重连成功 | 合并最新动作、轮次、结果与结束状态，保持展开与阅读位置 | 继续查看，不重启执行 |
| 程序退出后重启 | 原未结束轮次显示中断，已结束轮次和结果保留 | 回原任务明确继续，由 Context 重新安排 |
| 旧任务没有详细过程 | 展示可确认的角色、轮次、状态和结果，并说明“详细执行记录未保存” | 可读已有结果；此后新轮次按新规则记录 |
| 某项记录或结果不可读 | 原位置说明不可用，不解释为从未派发或没有结果 | 可重试读取，其他正常内容仍可查看 |

## 5. 验收标准

| 场景 | 预期 |
| --- | --- |
| Context 准备材料，尚未派发 | 只有真实主任务提示，没有虚构的子任务或完成记录 |
| 真实派发 Writing Agent | 可查看目标、归属、当前轮次、状态和动作时间 |
| 一个长动作刚开始 | 显示进行中，不提前标完成；没有新记录不伪造进度 |
| 正常结束但未提交结果 | 明示本轮结束、未提交结果，可回对话继续 |
| 已保存初稿后失败 | 初稿仍可读，失败原因同时可见，不误报整体完成 |
| 运行中请求停止 | 先显示正在停止，确认结束后显示已停止，记录保留 |
| 同一 Writing Agent 修改两轮 | 两轮分别组织，旧结果可读，当前动作不沿用旧轮 |
| 结构性重写或连续两次正文检查 | 新旧 Agent 可区分，检查始终指向具体版本 |
| 展开某轮的方案、初稿、检查或核对结果 | 只读打开，结论与对象一致，返回原记录位置 |
| 读历史时有新进度 | 不抢走阅读位置，点击新记录提示后才跳到最新 |
| 同作品或跨作品切换，原任务晚到结果 | 只更新原任务，返回入口准确，当前任务内容不串入 |
| 刷新或重连 | 展开项与阅读位置保持，不重发指令，不重复结果 |
| 重启，旧 Agent 不可继续 | 未结束轮次中断，历史正常结束轮次不改写，新安排独立记录 |
| 大量历史或旧数据缺少过程 | 逐段可读，明确缺失，不补造历史动作 |
| 单项记录损坏或结果无法读取 | 可重试该项，其他记录仍可查看 |
| 手机展开详情、读结果并返回 | 控件可达，正文只读，回到原子任务 |
