# 查看 Agent 执行过程：当前旅程

用户要求 Main 与 Sub 内部使用相同展示规则，保留完整可见过程；最新明确不同 Agent 的运行记录分别展示。思考与工具默认收起，相邻记录在各自的流内合并，Sub 从派发卡或输入框上方浮层进入。本轮同步修改现有 PRD 与可点击原型，保留单个文本审查者及设计验证；使用统计暂不做。

## 主线

作者在原任务向 Main 提出要求，主信息流保留作者消息与 Main 的过程，各 Sub 详情保留其自己的消息、思考、调用、输出、错误及执行事件。工具名与内容保留原文，所有 Agent 内部共用通用呈现。连续思考与普通工具按同 Agent、同次执行合并成默认收起的过程组，在各 Agent 自己的流中，消息、执行分界、结果或派发时断开，其他 Agent 活动不打断；原内容仍完整可读。

子任务派发保留独立的信息流卡片，输入框上方的子任务入口可向上展开浮层，显示当前与历史 Sub 的身份、真实任务、状态、最近已记录动作和保存结果。点行在同一浮层打开详情，将 Main 实际派发与补充的要求作为独立上下文，再看该 Sub 的完整过程与结果，顶部返回列表或关闭。浮层没有页面遮罩，输入与背景仍可操作，再点入口、关闭、Escape 或点外部可收起；主信息流位置保持。作者输入仍明确发给 Main，浮层打开保存结果后返回同一详情与阅读位置。

作者切换任务或作品，执行继续属于原任务。返回、刷新与重连补齐过程，不重发要求、不重复记录；停止指向实际执行任务。失败、停止和中断保留已有内容与结果，继续工作产生独立执行分界，新 Agent 不合并旧身份。

## 关键分支

| 情况 | 规则 |
| --- | --- |
| 尚未派发 Sub | 直接显示 Main 的完整可见过程；真实派发后才显示对应 Sub 的入口 |
| 默认折叠与相邻合并 | 思考、工具明细与技术原内容默认收起，运行中不自动展开；相邻思考与普通工具合并，原内容不丢失 |
| 折叠摘要与活动列表 | 简短动作摘要展开为按顺序排列的工具与思考活动，原名与完整内容可达；数量、时长有实际依据，运行与异常可见 |
| 内容来源 | 主流只展示 Main，各 Sub 详情只展示所选 Agent；派发要求是独立上下文，身份沿用所在视图，轮次与时间按需查看 |
| 子任务单独展示 | 输入区浮层与信息流派发卡并存，实际任务、状态与结果一致；无子任务明确空态 |
| 子任务浮层展开与关闭 | 向输入框上方展开，不锁背景；关闭、Escape、点外部收起，输入和阅读位置保持 |
| 并行执行或流式更新 | 各自的流按自身顺序与归属更新，Main 新记录提示仅对应 Main；保持展开与位置，参数、全部输出与错误可读 |
| 长内容、历史很多 | 可折叠与继续读取，但原文和完整历史可达，新内容不抢位置 |
| 暂不认识的工具、Agent 或内容类型 | 通用展示可读原内容，无法直接显示的部分说明类型和不可用情况，不整条丢弃 |
| 思考说明未提供或不可读 | 如实说明缺失，不补写；实际可读内容照常展示 |
| 浮层查看 Sub 时发送要求 | 明确接收方仍为 Main；关闭浮层后继续阅读原主信息流 |
| 工具结束、Agent 结束、结果保存 | 分别显示实际事实；执行结束不替代业务成功、作者定稿或资料应用 |
| 失败、停止或中断 | 保留参数、已有输出与保存结果，原错误可读；通过原任务入口继续 |
| 停止或程序退出时工具未返回 | 调用随所属执行显示已停止或中断、未收到最终返回，保留参数与已有输出，不补造返回 |
| 切换与晚到内容 | 只更新所属任务，停止指向实际执行任务，各任务输入和查看位置保留 |
| 重连与重启 | 重连补齐并合并；重启把未结束执行标中断，历史结束结论不改写 |
| 旧记录缺失或单项损坏 | 指明缺失范围，可重试单项，正常内容与结果仍可查看 |

## 功能模块

1. 看完整过程：分别查看 Main 与各 Sub 的真实可见内容，内部规则相同。
2. 定位与阅读：输入框上方的子任务浮层与派发卡，读全过程、打开结果再返回。
3. 离开与恢复：任务切换、刷新、断线、停止、失败及重启后的准确记录。

### 2026-10-06 · 信息流整体重做（成果优先）

走查结论：信息流答不出"现在在干什么、做出了什么、接下来我要做什么"，且已累积 7 轮补丁，按整体重做处理。用户确认两项分支决策：

1. Sub 交回的成果与结论显示在 Main 信息流的派发卡上。理由：这是 Main 派发调用收到的返回，属于 Main 自己的记录，不把 Sub 的过程混入主流。
2. Sub 详情从浮层改为固定高度的阅读面板（宽屏在右侧，窄屏全屏）；输入框上方浮层只保留子任务列表。

新的信息流旅程：

- **发起**：作者发送后，信息流底部立即出现"正在处理"实时行；任务进行中，发送按钮变为停止，输入文字后变回发送（补充要求仍发给 Main）。
- **过程**：Main 文字直接可见；思考与工具成组折叠，摘要为"动作 + 对象"，不显示步数；常规开始、结束分界不再显示，停止、出错、中断、定稿等非常规事件保留。
- **派发**：子任务卡以任务内容为标题、身份为次要信息；运行中第二行显示当前动作；输入框上方入口同步显示正在进行的子任务及其当前动作。
- **成果**：子任务结束后，卡片显示交回结果：成果条目可直接阅读，检查类结论用一句话显示；没有交回成果、失败或停止都如实说明。
- **收尾**：一轮结束后，过程收为"已处理 X 分 Y 秒"一行，派发卡与 Main 最后一条回复保持可见；进行中的一轮不收起。
- **Sub 详情**：从卡片或列表进入右侧面板，按时间展示：派发要求全文 → 该次执行过程 → 交回成果 → 补充要求 → 下一次执行……原始调用在要求内按需展开。成果在同一位置打开，返回回到子任务详情。
