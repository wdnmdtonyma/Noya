# Noya 小说 Agent 工具 · MVP

## 1. 背景与目标

长篇小说的问题不只是“模型记不住”，而是事实、打算、人物、世界规则和写法混在聊天记录里。书越长，旧方案、已否决内容和过时设定越容易被重新带进正文，作者不得不反复纠错。

Noya 让 context 来自这本书已经保存的内容，而不是一条越聊越长的对话。作者负责决定故事往哪里走，Agent 负责把相关材料找齐、写成正文，并在定稿后把新事实整理回书里。正常情况下，作者的注意力留在正文；只有发现问题时，才进入资料页查看、编辑或回退。

## 2. 用户经历

作者打开一本书，默认回到正在写的章节。选择第 13 章时，右侧进入第 13 章自己的对话；选择韩拾遗时，则进入韩拾遗自己的对话。不同对象之间不继承聊天内容，每次工作所需的材料都从书中重新组装。

作者可以先和 Agent 排这一章，再让它动笔。排章时确认下来的内容会写入“本章安排”，写作时读取这份安排，不读取排章对话。章节定稿后，正文中已经成立的新事实会同步进大纲、世界志、人物志、资料库和伏线；作者不需要逐项归档。

## 3. Context 的基本原则

- **书里的内容长期有效**：正文与资料文件是下一次工作的依据。聊天只服务眼前这件事，想长期生效的意见必须落实成正文、安排或资料改动。
- **每次按任务取材**：写藏经阁只取藏经阁所在地点链和真正用到的规则，不把整棵世界树、全部人物和所有范例一起塞进来。
- **不同内容承担不同责任**：正文记录已经发生的事，大纲记录作者决定的命运，世界志记录世界规则，笔法只约束怎么写。它们互相引用，但不能彼此冒充。
- **未知就是未知**：留白、未定去向和没有写过的能力都不能为了“完整”被自动补成事实。
- **只让最终结果继续生效**：已接受的修改进入正文或资料；被否掉的版本只留在历史里，不参与后续写作。

## 4. Context 包含什么

### 4.1 正文与本章安排

正文是已经发生之事的最终依据。连续写作默认读取最近三章全文，更早章节按章读取摘要；修改旧章时，读取目标章节、相邻章节和与它直接相关的资料。

“本章安排”承接排章与写作。它是一组可以逐条修改的具体安排，记录这一章已经决定要发生什么。排章和写作是两次独立工作，只有作者接受的本章安排会传入写作，排章对话中的试探、废案和闲聊不会跟过去。

### 4.2 大纲

大纲记录作者已经决定的命运。它按故事顺序连续阅读，可以同时存在已经写完的事实、眼前的意图和更远处的明确锚点。

- 作者只想好开头和结局时，中间可以整段留白。
- 写下一章只读取最近事实、当前意图和前方最近的明确锚点。
- 锚点只约束已经确定的结果，不替作者规定抵达路线；空白不会触发自动补剧情。

### 4.3 世界志

世界志记录所有人物都必须遵守的世界规则。空间信息是一棵树，按“界 → 大陆或海域 → 境域 → 势力或国家 → 机构 → 地点”逐层展开；风土和势力都挂在实际发生或统辖的位置。

当前舞台还需要四类运行内容：修行与自然、社会秩序、经济与资源、主角机制。写一章时，从世界志中取一条完整地点链，再补这一章实际会用到的运行规则。例如藏经阁场景会读取其所属路径、入阁价格、境界规则和签到限制，不读取无关地域。

普通的世界生长由 Agent 在定稿后直接归位。作者发现归错时，可以直接编辑、让 Agent 修改或从历史回退。

### 4.4 人物志

人物志记录一个人会怎样行动，以及他与谁有关。关系以当前人物为顶点，自上而下按亲缘、亲近、敌对、后辈、势力等关系展开；复杂分支可以聚合和收起。

每个人物只有一份自由 Markdown 文档。主角已经明确的修为、技能、物品和钱财自然写进人物小传；信息少的配角可以只有两三段，不用空字段把版面补齐。写章时读取主要登场人物的完整文档，次要人物只保留足以避免写错的一句话。

会反复出现且自身有稳定规则的技能或物品，不在人物志中重复解释。人物志只说明谁会用、谁持有和当前状态，完整说明放在资料库。

### 4.5 资料库

资料库收纳会被多次提及、且自身有稳定规则的命名对象，例如功法、术法、技能、丹药、材料、道具和关键物品。一次性普通物件不单独建档。

每个条目也是一份自由 Markdown 文档，只写已经明确的用途、限制、来源和当前状态。正文或人物志提到《引气诀》、父亲留下的玉等对象时，可以直接查看简介并进入条目；写章只读取本章真正会用到的条目。

### 4.6 伏线

伏线记录读者暂时看不见、但后续需要兑现或持续遮掩的内容。已经写进正文的伏笔、尚未写出的幕后推进和未来揭开的位置必须分开，事实与打算不能混成一件事。

- **重**：揭开后会改变读者对整本书的理解，默认优先关注。
- **轻**：兑现时提供一次局部回报，用完即可结束。
- **氛围**：只负责制造误导或不安，不主动发展，也不催促回收。

有明确去向的伏线，在抵达对应剧情段之前不提前揭开；还没想好的保持未定，不由 Agent 擅自补出答案。

### 4.7 笔法

笔法先说明这本书相信什么，再说明文字怎么落下。它是一篇连续的自由 Markdown 文档，主角眼下的处境、故事气息、景别、节奏和具体写法自然写在一起，不拆成作者需要维护的固定栏目。

文档后保留少量已经写对的范例。写一章时读取整篇笔法、最近定稿正文和一至两段与当前场景最相关的范例。第一次遇到重要新场面时，Agent 可以先给一段短试写；作者确认后才进入范例，但试写本身不算已经发生的剧情。

## 5. Context 怎样组装

### 5.1 一个对象一条对话

章节、人物和资料各有自己的对话。切换对象时，右侧对话随之切换；别的对话里说过的话不会进入这一轮。作者需要时可以展开查看本轮读取了哪些材料，但这只是一份简短说明，不是让作者维护的选择器。

### 5.2 不同任务读取不同内容

| 当前任务 | 必须读取 | 按内容补充 |
|---|---|---|
| 排下一章 | 最近三章全文、更早章节摘要；大纲的最近事实、当前意图和最近锚点；主要人物、相关伏线；笔法 | 场景确定后，补地点链、运行规则和相关资料条目 |
| 写下一章 | 已接受的本章安排；最近三章全文与更早摘要；大纲、主要人物、相关伏线；笔法与相关范例 | 本章实际用到的世界规则、物品与能力 |
| 修改正文 | 目标章节、相邻章节、本章安排、用户这次的修改意见 | 与改动直接相关的人物、世界规则、资料、伏线和笔法 |
| 修改资料 | 当前文档全文、直接引用它的内容、相关已写事实 | 会被这次修改连带影响的章节或其他资料 |

同一份资料不会因为“可能有用”就默认进入所有任务。场景、人物或物品尚未确定时，先完成剧情判断，再补它真正需要的 context。

### 5.3 不能混淆的边界

- 正文中的已定稿内容是已经发生的事实；未来大纲和伏线打算仍可修改。
- 世界志约束任何人到这里会发生什么；人物志约束某个人自己会怎么行动。
- 资料条目说明一个对象本身；人物志只说明人与它的关系。
- 笔法范例只提供语感和处理方式，不能把范例中的人物、措辞或情节照搬到新章。

## 6. 定稿后的同步与历史

章节定稿后，Agent 根据正文中真正成立的内容同步大纲、世界志、人物志、资料库和伏线。普通归档直接完成；关键人物、关键道具、新势力和新伏线会长期改变后续写法，必须先让作者知道，作者接受后才进入长期 context。

每次同步都保留改动历史。作者可以直接改文件、让 Agent 改，或退回旧版本。文件之间用引用连接，同一条信息只在最合适的位置完整说明，其他地方只保留关系和入口。

## 7. 长篇小说中的控制

书变长后，Context 仍按相关性组装，不读取整本书：近期正文保留全文，早期正文使用逐章摘要；世界志按地点路径和运行规则取用；人物、资料和伏线只取与当前任务直接相关的部分；笔法只取整篇短文档和一至两段范例。

故事进入新阶段时，Agent 根据大纲和已定稿正文调整笔法中与当前处境有关的段落，合并重复范例，把已经不合适的范例收进历史。历史不丢失，但不会因为存在过就继续影响新正文。

## 8. 验收标准

| 场景 | 预期结果 |
|---|---|
| 从第 13 章切到韩拾遗 | 对话和读取内容一起切换，不带入第 13 章聊天记录 |
| 排完一章后开始写作 | 只把已接受的本章安排传入写作，排章废案不进入正文任务 |
| 写藏经阁场景 | 读取完整地点链和相关价格、境界、签到规则，不读取无关地域 |
| 大纲只有开头和结局 | 中间保持留白，不生成补全任务，也不擅自规划路线 |
| 人物提到《引气诀》 | 人物志记录掌握情况，完整功法说明来自资料库，不出现两份互相漂移的解释 |
| 使用“天地铺开”范例 | 只借用场面尺度和节奏，不把试写内容当作已经发生的剧情 |
| 章节定稿 | 相关资料自动同步并保留历史，作者无需逐条确认普通归档 |
| 作者纠正一条设定 | 下一次相关任务读取纠正后的内容；被撤回版本不继续生效 |
