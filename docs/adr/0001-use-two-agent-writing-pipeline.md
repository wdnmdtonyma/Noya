# Use a Context-Agent-to-Writer pipeline

For each writing task, the author interacts with a Context Agent that restores the current position, answers questions, discusses the next chapter, and searches the existing work. Once the direction is settled, that Agent distils the accepted decisions into a Writing Brief, performs a final context search, and combines the brief with a focused Context Pack as a Writing Package. A fresh Writing Agent receives that package and first proposes a short Chapter Plan: a chapter overview and an ordered sequence of events showing their connections and consequences. The Context Agent checks the plan against author intent and available facts before prose generation, then reviews the resulting chapter for concrete failures to achieve the intended effect; the Writer can revise the plan and prose using focused feedback. This replaces the earlier prose-only handoff, without adding a third Agent or requiring the author to approve every internal step. Subsequent discussion explicitly leaves revision rounds uncapped for now: concrete requirement or fact violations must be corrected, while editorial suggestions do not independently block delivery. Each prose revision is followed by a whole-chapter recheck of the four agreed quality gates. Other stopping conditions remain to be defined, and improved reliability still requires real writing evaluations rather than a workflow alone. The Writer does not receive the complete author conversation, rejected directions, or raw search trail, and does not declare changes to official work context. After the draft returns, the Context Agent can still apply a Local Revision itself when the current Writing Brief remains valid; if the requested change requires the brief to change, it creates an updated package and delegates a Structural Rewrite to a new Writing Agent. Text length does not determine this boundary. Context updates are later derived only from finalized text, so material removed during revision never becomes an official fact. These are quality-oriented specialisations rather than capability restrictions. The MVP will not add a separate retrieval service or third retrieval Agent.
