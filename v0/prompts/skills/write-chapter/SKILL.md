# 写一章

## 收到通知时

| 通知 | 下一步 |
|---|---|
| 写手完成，提交了 `plan_N` | 第 4 步：检查方案 |
| 写手完成，提交了 `draft_N` | 第 6 步：派检查员 |
| 检查员完成，提交了 `review_N` | 第 7、8 步：处理结果或交稿 |
| 写手结束，未提交产物 | 读它的说明：能按要求澄清就 `send_message` 回复；需要作者决定就问作者 |
| 失败或被停止 | 告诉作者原因，问是否重新派出 |

## 1. 确认本章要求

- 只收作者已经接受的目标、事件、约束和结尾。讨论中被否定的想法、作者没接受的你的建议，都不放进去。
- 缺少会改变本章人物、事件或结果的决定时，先问作者，一次问清。非关键细节留白；作者允许你安排的，放进 `creative_scope`。
- 作者给的参考片段或写法示例，转述成写法要求放进 `requirements`，不把其中的人物、事件当作事实。

## 2. 查资料，整理 Brief 与 Pack

用 `query_canon` 取本章需要的材料：登场人物的当前状态、持有物与能力，相关世界规则，涉及的资料库条目，大纲位置，相关前文（关键段落原文，较远章节用能指回依据的短结论）。只收本章用得上的。

- **Pack**：每段以 `## 标题` 开头，段内一行 `来源：ID、ID`。尚未确定的事单独成段，写 `来源：无`，正文说明哪些事未知。
- **Brief** 字段：`schema_version`（1）、`id`、`chapter_id`、`mode`、`intent`、`requirements`、`constraints`、`ending`（未指定为 null）、`creative_scope`、`leave_open`。新章用 `write_chapter`，`chapter_id` 按已有章节顺延（先 `list` 章节）；重写已定稿章节用 `rewrite_chapter`，Pack 附原章正文，Brief 说明保留什么、改变什么。

## 3. 保存并派出写手

`save_package` → `spawn_subagent({ role: "writer", package_id })`。因有待同步章节被拒 → 本任务负责的章节按 `context-sync` 处理；工具指向另一任务时，请作者返回该同步任务，不接管其决定或停止状态。同步完成后等作者回到本任务明确继续。派出后简短告诉作者，结束本轮等通知。

## 4. 检查方案

读取方案，对照：Brief 每条要求是否落实；是否越过 `constraints`、替作者决定了 `leave_open`、在 `creative_scope` 外新增重要设定；事件因果是否成立；人物选择是否有依据；方案中"需要确认"的问题。

再看写法设计：每个场景都有场景卡；主角在爽点前真的吃亏；每个爽点都回指更早场景里的铺垫，决胜一招没有用前文没出现过的东西；设定交代挂在台词、判断、物件或动作上，不是整段旁白。缺了这些，按缺的项要求补，不替写手写。

- 有问题：`send_message` 说明哪里不对、要达到什么效果。需要作者决定的，先问作者。
- 没问题：`send_message` 回复"方案通过，写正文"。

## 5. 作者中途提出新想法

按是否推翻已有方向判断，不按改动字数：

- **追加调整**：改变了本章要求 → 先 `save_package` 保存新版本，再 `send_message` 并带上新的 `package_id`；只是补充说明 → 直接 `send_message`。
- **推翻方向**（改变关键事件的结果、人物动机的方向或揭示时机）：先用 `ask_author` 复述新方向与改变的关键事件，等待作者回答；确认后 `save_package` 并派新写手。

## 6. 正文检查

每份初稿都经检查才交给作者：`spawn_subagent({ role: "reviewer", draft_id })`。检查员不接收消息；对检查结果有疑问时自己补查，或派新检查员。

## 7. 处理检查结果

1. 先补查每条 `needs_verification`（`query_canon`）：查实是冲突的，并入问题；查实没问题的，排除；仍无法确定的，记下交给作者。待核实项本身不是修改指令。
2. 把 `violation` 发给原写手，每条写明位置（原文摘录）、依据、修正目标。编辑建议可附上，注明"不阻断，可取则改"。
3. 新初稿 → 派新检查员整章复查。

## 8. 停止并交稿

满足任一条件就交稿：

- 四项全部 `passed`；
- 同一冲突（同一门禁项 + 同一依据来源 ID）连续两轮没有修好；
- 可比较的相邻轮次中，冲突数量没有比上一轮减少；第一次检查没有上一轮，不用这条条件。

交稿时说明：检查结论、遗留问题和待作者决定的疑点、没有采纳的编辑建议；告诉作者初稿位置，不贴全文。提醒作者：在页面中从所读版本选择定稿，也可以继续提意见（回到第 5 步）；CLI 中可用 `/finalize`。

## 9. 纯措辞修正

作者只要求改字词、不改内容时：用 `edit` 修改工作副本 → `save_revision` → 派新检查员复查 → 交稿。不派新写手。页面作者引用了明确版本时，使用消息中指定的 `revision.md`（已经复制该版本），不能改成最新版；CLI 没有版本引用时使用当前写手的初稿文件。
